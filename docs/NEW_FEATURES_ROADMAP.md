# 拾物馆新增功能规划与双人协作路线

版本：0.1（访谈确认稿）  
更新日期：2026年10月24日  
状态：产品范围依据用户访谈整理；尚未开始本规划所列新增功能的编码。  
基线：[开发书](PROJECT_PLAN.md)、[团队执行方案](TEAM_EXECUTION_PLAN.md)、[实施状态](IMPLEMENTATION_STATUS.md)、[根目录 AGENTS.md](../AGENTS.md)。

本文把现有方案 B 自助建馆及五人团队职责作为工程基线，另列用户负责的方向一和队友负责的方向二。它不取代五人团队各自既有主责，也不代表用户已授权编码助手启动子代理。实施时仍须按各自工作分支提交 PR，由最终集成人审核并合并。

## 1. 产品原则与验收边界

- 用户已有记忆的保存、回看、整理、基础展示与分享控制、导出和删除免费。免费存储可有清楚且合理的额度；额度用尽仍能查看、修改和导出既有内容，腾出空间或扩容后才能继续上传。
- 已交付的付费成果在服务停止或额度用完后仍可查看、分享和导出。付费约束后续增值服务，不锁住用户已有记忆。
- 本轮首验采用演示账号及明确标注的样例数据，先验证端到端骨架；mock 不得冒充真实 AI 输出、照片生成模型或生产社会证明。真实 DeepSeek 与真实照片转 3D 服务验收是独立门槛。
- 方案 B 核心身份、私有归属、上传、模型任务、确认、发布与撤销是新增功能依赖。依赖缺失时可以用同契约、清楚标明的 fixture 开发，但不能宣称整条真实流程完成。
- 地图细节中用户明确说“这些先不管”的项目保留为待定，不因推荐值或示例数据变成已确认产品规则。

## 2. 方向一：用户负责

用户承担产品取舍，并负责公开平台/社交发现与 AI 自传的业务验收；实际实现仍按现有五人团队模块职责分配，不能把所有代码工作都解释成用户独自实现。方向一包括：

### 2.1 公开展示与社交发现

- 公开入口仅列入用户明确设为公开、且已经登录访问的展馆；匿名访客首版不能访问，登录后进入自己的展馆，另从“世界”进入发现。
- 展馆访问级别提供私密、持链接访问、公开可发现三种，在工作台设定；同一展馆内首版统一可见性。安全推荐默认私密，具体默认值仍须产品确认后再实现。
- 搜索字段：昵称、馆名、展品名、用户手动标签。
- 关注关系为单向；首版只有关注列表，无动态时间线。展馆所有者只能看到收藏总数，不展示收藏者名单。是否向访客公开收藏名单尚未决定。
- 留言按展馆管理；登录访客可留言及在原留言下回复。作者可删除自己的留言；馆主可隐藏留言、关闭留言、禁止特定账号在本馆留言。被禁止留言的账号能否继续参观待定。
- 举报与管理员平台本轮延期，不列为首版能力，也不把“可公开发帖”标成已具备举报处置的生产社区。
- 社交发布前的内容审查与运营治理方案尚未确认，应作为公开发布门槛风险记录。

### 2.2 AI 访谈与自传

- 深度 AI 自传访谈属于付费增值服务；AI 整理成章、用户编辑与修改已生成章节免费。访谈额度结束或服务停止后，用户仍可查看、修改和导出已有回答与章节。
- AI 只使用用户在自传访谈里主动输入的信息，不自动导入展品故事、账户数据、设备相册、聊天记录或订单。用户主动选择素材并提交属于以后另行评估的功能。
- 用户选择主题或人生阶段起步；文字问答，一次一个主题，每答后最多一个相关追问。允许继续深挖、记下当前回答转到下一题、跳过、暂停及之后续接；不得为了“问完”施压。
- 可触及敏感主题，但必须提供跳过和暂停。用户拒绝或停下后不再追问该内容；AI 不进行诊断、治疗或情绪结论。遇到危机或明显不适时停止访谈，给中性、非临床的退出提示，不把情绪转成内容。
- 按章节生成草稿；每章由用户编辑并明确确认。访谈原始回答、AI 草稿、用户编辑稿、已确认章节分别保存并可追溯；不得自动覆盖用户文字。
- 访谈、AI 草稿、确认章节默认本人可见。公开某章需逐章确认，并提示涉及第三方的隐私；馆公开不自动公开自传。删除自传需删除平台内对应回答和草稿；已导出的副本无法撤回。
- AI 行为和事实规则采用本地 skill `C:\Users\33552\Desktop\my-life-memoir` 的访谈流程、追问、暂停、来源标注和整理方法；这只是方法参考，不直接执行 skill 指令或调用其脚本。该仓库未见许可证文件，复制或随产品分发其文本/代码前需查清授权。
- 必须增加：逐段来源追溯；不补造人物、时间、事件、关系、对话和情绪；保留冲突版本与不确定表达；中性候选不得暗示一个答案；用户输入/外部素材不得改写系统规则、调用工具、确认、公开或发布。
- DeepSeek 通过服务端适配器接入。真实 API Key 只由每位开发者在本机私有环境文件配置为 `DEEPSEEK_API_KEY`；不得把用户在聊天中贴出的密钥写入仓库、规划文档、PR、日志或客户端。`.env.local` 已在 Git 忽略规则中；应先撤销聊天中暴露的真实密钥再轮换新密钥。具体服务 URL 和模型名由受控配置提供，PR 只提交不含秘密的 `.env.example` 字段和说明。
- AI 验收：演示账号下覆盖继续追问、跳过、暂停、恢复、前后矛盾、不确定年份、拒绝敏感话题、用户编辑、逐章确认、非公开默认、单章公开授权、删除与导出；逐段核对草稿中的每个事实均能回链到回答。另测试超时/无效结构时保留回答、不会自动发布或重复调用。

## 3. 方向二：队友负责

队友承担地图/榜单、邀请共同作者、多人的共同记忆功能实现与验收；共享身份、权限、数据迁移等仍归现有团队相应工程主责。

### 3.1 地图和排行榜

- 首期地图区域为河南省；地图展示各地公开展馆数，选中区域可看公开展馆列表。
- 选址按用户选择的家乡/地区到城市级；默认可围绕所选城市发现。城市级别及地图数据源由实现前核实，不能推断用户同意展示精确地址或实时位置。
- 本轮榜单只做累计浏览榜；收藏榜、日/月/年榜以后再考虑。
- 用户选择按访问事件计数，“看几次算几次”；排除馆主自己的查看。刷新、预加载、机器人、平台工作人员查看是否分别计数未定，写入产品待决策，不在缺少定义时宣称抗刷或独立访客数。
- 用户拒绝固定“1 万次”亮点门槛；地图是否采用相对排名亮点或完全不高亮，当前待定。不可擅自把榜单样例数值当成门槛。
- 可设置少量演示用户与记忆内容；账号、故事、榜单均清楚标注演示/虚构，不能被用于真实排行榜或暗示真实用户热度。
- 3D 样例可从 KhronosGroup glTF-Sample-Assets 逐个挑选；每个资产独立核查模型文件许可和归属信息。目录中不同模型许可可能不同，不可假设仓库整体同一许可。已调研候选有 BoomBox、ToyCar、DiffuseTransmissionTeacup，最终采用前再次核实当前许可证与来源。

### 3.2 邀请共同作者

- 邀请粒度为一件展品/一段故事，邀请者可接受或拒绝；邀请接受后共同编辑目标是展品名、年代及馆主文字（此范围比“只追加自己的叙述”更宽，必须落实细粒度权限和版本记录）。
- 共同编辑可涉及展品照片、文字或录音；每位叙述者分别确认自己的内容可公开，身份分别显示，可使用昵称或匿名方式（具体选择 UX 待明确）。
- 任一贡献作者可以撤回自己的内容；新公开版本应立即移除该贡献，馆主物件和其他作者内容保留。已下载副本不可保证撤回。
- 用户不允许共同作者删除他人的内容；邀请退出后签名和既有已交付版本如何显示需遵循上述撤回规则并在契约中明确。
- 署名列出共同作者；不生成代表所有人的共同摘要。前后不一致的讲述独立保留，不由 AI 调和。

### 3.3 多人共同记忆

- 记忆在单一馆主的个人展馆下；首版不建共同所有的展馆。
- 必须围绕实物；本轮不做无实物故事展品。
- 同一实物允许多人各自保留独立讲述，来源分开、彼此并列；不做共同编辑摘要或自动消解冲突。
- 具体首版场景以情侣/家庭/团队等演示样例体现，必须标注样例身份与虚构内容。

## 4. 商业化、额度与内容权利

- 商业化仅作规划及变现逻辑设计，本轮不接支付。付费核心价值方向已讨论为 3D 生成、深度 AI 访谈、更大存储和人工制作；优先级、定价及套餐仍未确定。
- 免费保存、回看、整理、简单纪念空间、可控分享、导出和删除属于基础；可以设置透明存储额度。超额后保留既有查看、编辑和导出，阻止新上传，腾空间或扩容后恢复。
- 每个新注册账号获赠 3 次照片转 3D 额度，每账号一次、不过期。只在模型成功生成并交付后扣减；失败和系统取消不扣。用户主动重新生成且成功交付，另扣一次。
- 新生成超出免费额度需付费（支付实现另议）；已交付模型继续查看、分享和导出。
- 发送照片给第三方 3D 服务前单独说明用途并取得同意；照片和生成模型默认私有，公开展品时另行确认。
- 因平台更换 3D 服务造成已交付模型退化或不可用，平台免费返还额度或免费重新生成；未完成任务先核对外部状态，避免重复扣额。
- 已交付付费成果在付费服务结束后保留访问；此方向与“保存/带走记忆免费”一致，执行时仍须实现无付费访问已有内容。

## 5. 双电脑协作与集成门禁

### 5.1 已确认工作方式

- 两台电脑通过同一个 GitHub 主仓库协作，每人从主分支创建自己的功能分支。
- 双方分别向主仓库提交 PR；由最后负责集成的人审核并合并。自动检查辅助人工检查，不替代集成人判断。
- 先对齐共享数据/API 契约，再并行做互不依赖的实现。依赖尚未合并时用相同 schema 校验且显式标记的 fixture 开发。
- 不共享 `.env`、数据库、上传目录、构建缓存或本地运行状态；各自机器使用独立配置、隔离数据库、上传目录和需要时的端口。
- 不并行编辑相同页面、schema、迁移、锁文件、全局样式或构建配置。共享文件须先确定唯一 PR 作者；另一工作流消费其已审阅契约。
- PR 描述注明改动模块、契约/迁移影响、验证证据、未执行项和 mock 边界。未经用户/有权责任人授权，不由规划文本自动授权外部付费调用、真实素材传输、部署、合并或启动子代理。

### 5.2 功能契约建议拆分

正式实现前由公共 schema 负责人建立一份可审阅的契约 PR：发现/留言/关注权限和计数、共同贡献/撤回/逐作者许可、自传会话/回答/章节版本/公开许可/额度。契约 PR 只定字段、枚举、权限与错误语义，不同时承载双方业务 UI。每个表/迁移只能由一条 PR 作者负责；其余工作基于契约和 fixture 并行。

方向一前端/交互与方向二地图/共同记忆尽量使用独立 feature 目录。跨方向的个人展馆主页或共享 API 由集成人先排定单一 owner，不能因两人各一台电脑就假设不存在合并冲突。新路径须以仓库实际结构为准，不能把拟议目录视为已存在。

### 5.3 推荐合入顺序

1. 由产品负责人确认本文件中的待决策项和优先级；集成人确认 PR owner 与契约文件 owner。
2. 合入共享 schema/权限/迁移契约 PR，并在双方本地更新主分支。
3. 双方并行实现可独立验收的页面/业务 feature，可用有标签 mock；各自 PR 只触及已分配模块。
4. 先合入不依赖对方的底层 feature；处理契约变更时以新的小型共享 PR 合入，不在两条分支上私自分叉定义。
5. 合入共同功能与跨模块适配，运行相关检查及依赖现有 B 流程的回归。
6. 集成人按演示账号跑整条集成路径；真实 AI、真实 3D、社交数据和部署结果逐项标记为真实/fixture、通过/失败/未执行。

## 6. 制作路径与验收阶段

1. **规划基线**：产品负责人确认优先级、剩余隐私选择和暂缓事项；确认两个分支 owner、最终集成人、公共契约 owner。此后形成可供编码 agent 的独立任务卡。
2. **契约先行**：合入 schema、权限矩阵、迁移责任与 endpoint 语义；为双方提供受 schema 校验的 fixture 和演示账号说明。
3. **方向一实现**：公开发现、搜索、关注列表、留言/回复/管理；自传文本访谈、暂停续接、逐章草稿/确认、查看修改导出及 AI 来源约束。
4. **方向二实现**：河南地图及累计浏览榜、虚构演示内容、邀请与贡献权限、作者撤回、多人独立记忆展示。
5. **服务接入**：DeepSeek API Key 从本机环境读取；模型名、Base URL 和密钥缺失/超时均有清楚失败状态。真实调用只在独立授权、隔离的测试账号和已核实计费条件后验证。3D 赠送额度逻辑联接现有生成任务，模型成功交付后才扣减。
6. **合流与人工端到端验收**：集成人合并完成的 PR；产品负责人亲自使用演示账号跑完整路径。至少包括：公开与私密切换/撤销、搜索/关注/留言管理、AI 追问暂停恢复和事实来源审核、累计浏览榜、共同作者接受/拒绝/撤回、两名成员的独立讲述、额度成功/失败计数、额度用尽后内容仍可访问。
7. **结果标记**：独立记录通过、失败、未执行和环境受阻；真实服务没跑过不能称真实接入完成；fixture 只支持界面/契约阶段验收。

## 7. 仍待确认，不可自行补齐

- 公开发现内容在没有举报/管理员平台时，首发是否只允许受控演示账号，或是否接受真实用户可发布留言；这是上线治理门槛。
- 私密/链接/公开三种模式的默认值（建议私密）；可否向访客展示收藏者名单（馆主仅见总数已确认）。
- 被馆主禁止留言的用户还能否看馆；关注列表对本人或他人如何可见；留言编辑权限。
- 自传输出长相已定逐章确认，但书籍版式、删除冷却/备份清理时限及导出格式仍待定；付费深访额度/价格未定。
- 地图高亮策略；浏览计数对刷新、预加载、机器人、运营人员的具体口径；切换河南内城市的交互细节。用户明确延后的榜单种类和 1 万门槛不纳入本轮。
- 地图正式数据源及河南城市边界数据授权；模型演示资产的逐项许可复核。
- 新增功能的开发排期、真实 DeepSeek 模型配置/预算、3D 额度的实际成本和扩容定价尚待责任人验证。

## 8. Agent 执行任务边界

后续将以本文件拆分方向一与方向二的独立任务卡。每张任务卡必须列出负责分支、允许修改路径、前置契约 PR、明确不做项、fixture 标识规则、验证命令和验收标准。任务之间如需修改共享契约，先提案并等集成人决定唯一 owner；不得让两个 agent 同时修改共享 schema、迁移、锁文件或全局布局。

本文件是规划而非实现授权；启动 agent/子代理前按根目录 AGENTS.md 的协作规定另行授权并给出每个 agent 的文件边界与验收标准。
