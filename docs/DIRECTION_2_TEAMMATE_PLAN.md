# 方向二：队友负责的功能规划与制作方案

版本：0.1（访谈确认稿）  
日期：2026年10月24日  
基线：[新增功能总路线](NEW_FEATURES_ROADMAP.md)、[开发书](PROJECT_PLAN.md)、[团队执行方案](TEAM_EXECUTION_PLAN.md)、[实施状态](IMPLEMENTATION_STATUS.md)。

## 1. 目标

队友负责地图与累计浏览榜、邀请共同作者、多人的共同记忆三组功能。它们运行在既有方案 B 的个人馆、登录、权限、分享快照和用户归属之上。队友对该方向实现和 PR 负责；公共身份、数据库、迁移、权限与部署仍由现有五人职责中的相应 owner 管理。首轮使用明确标注的演示账号和样例。

## 2. 地图与排行榜

### 2.1 首版范围

- 河南省范围；地图按地区展示公开馆数量，选地区进入公开馆列表。
- 用户选择展示地区/家乡，精确到城市级；不展示精确住址和实时位置。可否在河南地图中手动切换其他城市尚待确认。
- 只做累计浏览榜；收藏榜及日/月/年榜延后。
- 访问按事件计数，馆主查看排除。不能将“浏览次数”称为独立用户数。
- 用户拒绝 1 万次固定点亮门槛。相对 Top N 高亮、无高亮或人工推荐均未定；先用不高亮的中性地图骨架，不自作主张实现阈值。
- 允许少量演示账号与记忆，由制作方拟定；必须有明显演示标签，不能混入真实排名或作为社会证明。
- 用于展示的开源 3D 模型须逐文件核对许可与归属，记录来源链接、模型路径、许可文本/版本和使用范围；不默认整个 Khronos glTF-Sample-Assets 仓库许可相同。

### 2.2 计数规则边界

已确认：一次访问可以计一次、馆主自看不计。待产品明确的计数情形包括：浏览器刷新、自动预加载、机器人/爬虫、平台工作人员查看、用户登录设备跨端访问。实施前至少定清事件触发点与馆主排除身份，接口/数据库明确标记 `view_count` 为次数而非人数。当前无 1 万门槛，不把演示排序样例中的数值当真实计数或高亮标准。

### 2.3 数据与地图

- 地图城市边界和底图数据源需核实许可、技术格式、更新方式和河南覆盖范围后再定，不假定某个服务已有授权。
- 存储城市级用户选择的地域；发现查询只返回用户同意公开的粗粒度地域，服务端不得返回地址或未经授权的坐标。
- 地图上的馆数与榜单均只查公开状态下当前有效的馆/快照；停止公开后从公开列表移除。
- 对重复请求、防刷、刷新是否计次等若尚未决策，产品说明不得声称具备防刷或唯一访客统计。

## 3. 邀请共同作者

### 3.1 用户确认的行为

- 邀请对象粒度为展品/故事。被邀者可以接受或拒绝；拒绝或待回应不能视为已共同署名。
- 接受后允许编辑：展品名称、年代、馆主文字；也可提交自己的文字、照片、录音。因原选择授权范围宽，必须以字段级权限实现并保留修改来源/版本，不能只做自由编辑整个数据库记录。
- 各作者各自确认自己的贡献可公开；署名列出共同作者。每位作者可选择昵称或匿名身份呈现，具体 UI 与保存字段待契约定稿。
- 作者可撤回自己的贡献；撤回后新的公开版本立即不包含该贡献，其他人的叙述和馆主物件留存。已下载副本不可保证撤回。
- 任何作者不能删除另一人的内容。馆主/发起者是否可以隐藏某一作者内容而不删除、如何处理审核问题仍需产品和权限契约确认。
- 不生成代表所有作者的共同摘要；各自讲述并列，记忆冲突保留，不让 AI 裁决事实。

### 3.2 推荐状态模型

正式 schema 需由共享契约 owner 拍板。建议先显式区分邀请 `pending / accepted / declined / revoked`、作者贡献 `draft / confirmed / withdrawn`、对外展示授权 `private / public-consented`。这些是规划建议而不是已存在的数据枚举；并发邀请、重复响应、撤回后的重新邀请必须有确定结果和版本冲突处理。

## 4. 多人共同记忆

- 一个物件下可有多个讲述者各自叙述，同一馆主个人展馆承载该展品；首版不建共同所有展馆。
- 必须有对应实物；无实物的故事展品本轮不做。
- 讲述、来源、作者与公开同意分别保存；不建立“大家一起编辑的一段总结”，不让后提交内容覆盖他人叙述。
- 展示上明确区分对象主人的基础展签和各贡献者记忆；具体组件设计由实现前与方向一的参观页 owner 协调，不能双方修改同一参观页文件。
- 记忆冲突并列展示或标注各自说法，不能由 AI 合并为确定事实。

## 5. 依赖与文件边界

- 依赖现有登录身份、个人馆归属、公共 schema、分享访问、发布快照和撤销。访客可见内容需检查当前公开授权及贡献者自己的同意。
- 地图只读取公共展示数据，3D 场景不直接调用数据库或 AI。榜单统计、地理粗化、作者撤回和公开权限由服务端权威实现。
- 地图、邀请/贡献 UI 和共忆展示尽量独立于方向一的 AI 自传/社交主要页面；实际目录通过检查仓库后选定。禁止为避免冲突凭空创造重复用户或分享子系统。
- 数据 schema、迁移、共享展示契约只由指定 PR owner 修改。队友先用已审阅契约提供的 fixtures 开发，不自行复制类型、枚举或权限规则。
- 城市地图资产、3D 模型样例作为显式列出的静态演示资源，记录许可证与来源；不要将未授权数据打包。

## 6. 制作步骤

1. **需求冻结**：产品 owner 确认地图高亮、刷新的计数、河南城市切换、禁评后观看、共同作者的匿名字段和馆主隐藏权限。
2. **地图/排行数据调查**：确定河南边界文件、地图渲染方案和许可；候选模型逐项复核许可与资产事实。输出轻量技术选型记录，避免不必要的新依赖。
3. **契约 PR**：公共 owner 定义公开馆数量、累计访问事件、粗粒度地域、邀请/贡献/同意/撤回 schema，错误码、访问权限、迁移边界及删除语义。不能在队友业务 PR 里同时修改另一个模块的共享迁移。
4. **演示 fixture**：准备少量标注演示用户、馆、展品、城市和榜单数据；明确样例浏览次数是假数据，只用于 UI 展示，不参与真实统计。
5. **地图和榜单骨架**：实现河南地图、地区馆数、城市选择/列表和累计榜；访问事件边界与馆主排除由服务端实现；待定高亮先保持关闭。
6. **共同作者**：接受/拒绝邀请，按字段保存独立贡献、署名和用户授权，版本化编辑，作者撤回后更新公开快照。测试他人内容不可删除。
7. **多人共同记忆展示**：同物件并列多作者讲述及各自来源；实物仍由一位馆主承载，不做无物叙事与共同摘要。
8. **PR 和集成**：按下节规则提交独立 PR；最后由集成人合并后，产品负责人以演示账号跑多账号权限、地图/榜单与贡献撤回全路径。

## 7. 验收标准

| 项目 | 通过条件 |
|---|---|
| 地区隐私 | 只保存/返回明确同意的城市级地域；公开页面无精确住址/坐标；私有或撤销的馆不在地图 |
| 地图范围 | 河南城市边界来源及使用许可记录齐全；地区馆数与公开馆过滤一致 |
| 排行榜 | 只显示累计浏览次数；馆主自看排除；计数语义显示为次数；不显示收藏榜或日/月/年榜 |
| 高亮 | 未获新决策前不使用 1 万次或隐含高热阈值；样例数值标演示 |
| 演示内容 | DEMO 账号/故事/次数与真实用户严格隔离，有来源/许可记录 |
| 邀请 | 未接受不署名；拒绝/过期/撤回的状态清楚；重复操作返回确定结果 |
| 作者权限 | 每个人仅编辑协议允许字段；任一作者不可删除他人贡献；馆主与其他作者的动作有审计来源 |
| 公开同意 | 每位贡献者对自己的内容独立同意；未同意内容不进入快照；撤回后新请求和新快照不再返回该内容 |
| 共同记忆 | 多人故事独立保存/展示；冲突不被合并；首版仅实物条目和个人馆承载 |
| 多用户隔离 | 至少两个演示账号验证列表、详情、修改、素材和撤回权限，不依赖前端隐藏按钮 |

## 8. 双电脑、Git 与 PR 约定

- 在同一个 GitHub 主仓库上从主分支建立队友独立功能分支；不要与方向一共用工作分支。
- 完成后向主仓库开 PR；由最后的集成人审核并合并。队友对自己 PR 的实现、检查证据和修复负责。
- 各电脑分别设置隔离 `.env.local`、PostgreSQL、上传目录和构建目录；不复制真实数据库或密钥，不共享构建缓存。任何真实模型/API Key 不入 Git。
- PR 限定本方向实现路径；公共 schema、迁移、锁文件、根布局和全局样式须先登记唯一 owner。涉及方向一共享参观文件时先向集成人确认是否由队友修改。
- PR 说明 fixture 与真实数据边界、迁移顺序、权限检查、验收命令、未执行项目。改动涉及权限/发布/迁移时遵循现有 AGENTS 的交叉复核或单人自查记录。
- 契约未合入时可用相同 schema 校验的演示 fixture；不得把 fixture 的馆数/浏览量当真实产品数据。

## 9. 不做和待确认

- 本轮不做收藏榜、日/月/年榜、1 万次点亮、全局/全国地图、无实物故事、共同所有展馆、共同摘要、举报管理员平台。
- 仍待定：相对高亮或完全不高亮、刷新/预加载/机器人/平台查看计数、河南城市切换、地图数据源、禁止留言后是否可参观、留言编辑、作者匿名 UI 和馆主隐藏他人贡献的边界。
- “累计访问按几次算几次”已确认；在具体边缘条件未定前，不宣称防刷或独立访客口径。
- 开源模型和地图数据许可须逐项复核；未核清的资产不用于发布构建。
