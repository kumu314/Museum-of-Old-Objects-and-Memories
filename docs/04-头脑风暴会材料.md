## 1. 唯一还成立的硬输入：选题标准本身

`docs/03` §1 那张表仍然有效——6 个赛道 + 每个赛道两条验收线，这是「套用」的那部分：

| 赛道 | 验收线 A | 验收线 B |
|---|---|---|
| 办公 | 真实任务（会前简报 / 会议待办 / 汇总周报，选一件做好） | 交付能用（输入需求→完成任务→结果拿来就能用） |

## 2. AI 评审意味着什么（今晚唯一能提前准备的新变量）

| # | 推论 | 可信度 | 对应动作 |
|---|---|---|---|
| 1 | **材料必须逐字覆盖两条验收线**，用它的原词，不要同义改写 | 高（rubric 型评审的通用行为） | 写产品定义时，两条验收线的原文各占一个小标题 |
| 2 | **AI 对数字敏感、对形容词不敏感** | 高 | 每个作品必须有一句「从 __ 到 __」，且带分母 |
| 3 | **AI 读不到"能不能真的跑"** | 高 | 用**录屏 + 可复现命令 + 截图**证明，不能靠口头说"跑通了" |
| 4 | **现场手感 / 氛围的价值下降，文档质量的价值上升** | 中高 | ⚠ 我上一轮基于"人气投票"抬高"3 秒看懂"权重的推论**作废**（§10 第 3 条） |

| 6 | AI 评审**读什么、用什么 rubric、有没有人工复核**——全未知 | — | 明天必问（§7） |

**一句话**：AI 评审把"能不能讲得动人"换成"能不能被逐条核对"。这对我们是净利好——`docs/02` 那套「契约先行 + 读数说话」正好是这个形状。

## 3. 今晚该定什么 / 不该定什么（v3 修订）

### 3.1 「收敛三个」的正确含义

三个候选**不是三个选项**，是**三种能力的兜底**。判断标准只有一条：

> **三个候选各自要求的核心能力，互不重叠。** 否则三个等于一个。

| 候选 | 核心能力要求 | 赛前可完成 | 主要翻车点 |
|---|---|---|---|
| **用餐** | 数据整理 + 约束求解 | **65–70%** | 容易被判"不就是点菜器" |
| **游戏** | 前端手感 + 审美 | 60–70% | "想再玩一局"证明不了 |
| **办公** | API 接入 + prompt 工程 | 50% | 最挤 + 唯一有外部依赖 |

三种能力（数据/前端/接口）互不重叠 ⇒ 这个组合**成立**。

**但它的价值要说清楚**：真正被对冲的**不是 rubric 偏好，是"我们自己的能力判断"**。
理由：队友技能栈至今完全空白（`docs/03` §9 第 4 条）。如果 5 个人里没人能碰前端，游戏当场作废；没人愿意整理真实菜单数据，用餐当场作废。
**这才是今晚最大的未知，也是今晚第一件要解决的事。**

### 3.2 能定 / 不能定

| ✅ 今晚可以定（明天不会推翻） | ⛔ 今晚别定（明天会推翻） |
|---|---|
| **5 个人的技能栈与意愿**（客观事实） | 具体选题的最终形态、名字、功能清单 |
| 6 赛道 → **3 个互不重叠的候选** | 分工的细颗粒度（要等选题定了才能分） |
| 每个候选写一句「从 __ 到 __」 | 提交材料的模板与字数 |
| 5 人的**角色框架**（谁写代码 / 谁做材料 / 谁演） | 评分策略（权重不知道，无法优化） |
| **明天听会的分工**（谁专听哪一块） | 技术选型、UI 风格 |

**为什么**：明天的准则会改变权重。今晚锁死 = 用旧权重做新决策，明天听完还得改，等于今晚白开。
**维持现状的代价**：如果今晚什么都不定，明天听完准则只剩 2 天，赛前资产来不及做——所以「方向」必须今晚收敛，「形态」必须留到明天。

## 4. 选题评分卡

**先过门槛，再比分数。技能栈是前置约束，不是评分项。**

### 4.0 前置约束（今晚新加，优先于评分）

| 约束 | 判据 | 不满足的后果 |
|---|---|---|
| **C0 技能栈** | 每个候选至少有 **1 人**明确说"这块我能独立做" | 无人认领 ⇒ 该候选直接出局，不看分数 |

> 这条放在评分卡之前，是因为评分卡打的是"这个选题有多好"，而 C0 问的是"我们做不做得出来"。
> 好选题 + 没人会做 = 零。

### 4.1 门槛（不过就淘汰，不计分）

| 门槛 | 判据 |
|---|---|
| G1 | 两条验收线都能**用一句话说清怎么命中** |
| G2 | 能写出一句「从 __ 到 __」，且分母说得出来 |
| G3 | 能演一条**异常路径**（空输入 / 超长输入 / 断网 / 乱码，任选其二） |

### 4.2 排序分（7 维 × 0–2 分，满分 14，≥10 进决赛圈）

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| **P1 可量化对比** | 说不清前后差别 | 有数字但靠估算 | 有分子分母，能现场复现第二遍 |
| **P2 异常路径** | 只演正常路径 | 想过没实现 | 两档以上有降级动作 |
| **P3 闭环完整** | 只做了中间一段 | 缺"数据留下" | 输入→处理→输出→留痕全通 |
| **P4 一眼看懂** | 要讲 1 分钟 | 讲 20 秒 | 看标题就明白 |
| **P5 可被核对** | 只有我们能操作 | 评委能看不能点 | 有录屏/截图/命令能自己复现 |
| **P6 壁垒** | 谁都能做 | 有点巧思 | 有真实数据或领域规则，复制要几周 |
| **P7 少外部依赖** | 断网就废 | 需联网但可控 | 断网也能完整演一遍 |

> **失效边界**：这张卡衡量"通用得分点"，**不含明天的实际 rubric**。明天听完准则后，权重要重排一次。

## 5. 5 个人怎么分：不是合规问题，是效率问题

| 团队规模 | 沟通链路数 C(n,2) |
|---|---|
| 4 人 | 6 条 |
| **5 人** | **10 条**（+67%） |

| 方案 | 分工 | 好处 | 代价 |
|---|---|---|---|
| **① 4 主 + 1 支援**（推荐） | 2 开发 + 1 产品/材料 + 1 演示，第 5 人专职"真实数据 + 验收测试 + 录屏" | 主线只有 4 人沟通（6 条链路）；第 5 人干的是别人干不了的活 | 第 5 人不写主线代码，可能有"我没参与"的落差 |
| **② 2+2+1 双线** | 拆两个子方向各 2 人，1 人统筹 | 两条线都有产出，等于买保险 | 两套材料、两套演示；5 人摊成 2.5 人/线，两条线都做不深 |

**判断**：选 ①。理由不是"5 人不行"，是**校赛周期短、材料与验证的工作量被低估**——第 5 人干"数据 + 验证 + 录屏"的边际产出，高于他挤进代码主线的边际产出。

⚠ 前提：这个判断依赖"第 5 人会做数据整理与测试"。如果 5 个人全是开发、没人愿意做材料，方案要改成 ②。
**今晚不用定方案 ①②**——先拿到技能栈，明天选题定了再套。

## 6. 今晚议程：45 分钟（v3 重排）

> **重排的理由**：v2 把「筛赛道」放前面，但筛赛道是**主观打分**，容易被第一个说话的人带节奏；
> 而技能栈是**客观事实**，先拿到它能直接约束后面的筛选。**先客观、后主观。**

| 时长 | 事 | 具体怎么做 | 产出 |
|---|---|---|---|
| 5 min | 对齐 §0 三条 + §1 赛道表 | 念一遍即可，不讨论 | 无争议基线 |
| **12 min** | **技能栈摸底**（§6.1） | 每人 2 分钟，说三句 | 一张 5 人能力表 |
| **12 min** | 6 赛道筛到 3 个（§6.2） | **先各自独立打钩，再对齐分歧** | 3 个候选 |
| 8 min | 每个候选写一句「从 __ 到 __」 | 逐条过 §4.1 的 G2 | 3 条可验证句子 |
| 5 min | 明天听会分工 + 死线（§6.3） | 定人、定问题、定时间 | 听会任务单 |
| 3 min | 列赛前共享资产（§6.4） | 只列，不分配 | 待办清单 |

**会上别做**：技术选型、UI 设计、"还能加什么功能"。这三件现在讨论，等于提前烧掉赛中的决策额度。

### 6.1 技能栈摸底（今晚最重要，12 分钟）

每人 2 分钟，**只回答三句**，不展开：

1. **我做过的最复杂的东西是什么**（说一个具体的：一个页面？一个脚本？一次数据分析？）
2. **10/21–10/25 我每天能投入几小时、大概什么时段**
3. **我最不想做什么**（写前端 / 写接口 / 整理数据 / 上台讲 / 做 PPT）

> 第 3 句比第 1 句重要。**"不想做"比"不会做"更致命**——不会可以学 2 小时，不想做会一直拖到截止。

**产出格式**（当场记在共享文档里）：

| 人 | 做过最复杂的 | 每天可投入 | 不想做 |
|---|---|---|---|
| 1 | | | |
| 2 | | | |
| 3 | | | |
| 4 | | | |
| 5 | | | |

**为什么必须今晚问**：这是 `docs/03` 里唯一一个"完全空白"的变量，而它直接决定三个候选里哪个真的可行（§4.0 的 C0）。

### 6.2 6 赛道筛到 3 个（12 分钟）

**做法**（关键是"先独立、后对齐"，避免从众）：

1. 每人先在纸上给 6 个赛道打钩：**"这条我们能做出来吗"**（能 / 不能 / 不确定）
2. 报数，把「不能」≥2 票的直接淘汰
3. 剩下的按 §4.1 的 G1/G2/G3 过一遍门槛
4. 若剩超过 3 个，按 §4.2 打分取前 3

**已知的推荐顺序**（`docs/03` §3，可作参考但不强推）：**用餐 > 游戏 > 办公**。
排除理由：短剧（交付物不是代码，协作底座失效）、查证（检索层零资产）、OPC（没有真实客户）。

⚠ **这个顺序在今晚可能被推翻**——如果技能栈显示没人能做前端，游戏出局；没人愿意整理数据，用餐出局。**以技能栈为准，不以我的推荐为准。**

### 6.3 明天听会：分工与死线（5 分钟）

**听会分工**（一个人听全会容易漏，5 个人分头听）：

| 人 | 专听 | 记什么 |
|---|---|---|
| 1 | **rubric 结构** | 是不是那 12 条验收线？有没有额外维度？各占多少分？ |
| 2 | **AI 评审的输入与机制** | AI 读什么材料？有没有人工复核？用什么模型？ |
| 3 | **提交形式与截止时间** | 交什么文件？交到哪？几点截止？要不要现场拷？ |
| 4 | **赛道与组队细则** | 6 个赛道是否全开？会不会某赛道取消或合并？ |
| 5 | **注意事项 / 红线** | 什么会被扣分或取消资格（抄袭、用现成模板、超时） |

**散会后 2 小时内必须定选题**（建议死线：明天会散后 +2h，且不晚于 22:00）。
理由：10/23 一整天要做赛前资产，定得越晚，能提前做的越少。

**兜底规则**（防"议而不决"）：**若死线时仍定不下来，默认执行「用餐」**。
判据不是"它最好"，是它**赛前可完成比例最高（65–70%）**——万一明天还得改，沉没成本最小。这是可证伪的兜底，不是"到时候再看"。

### 6.4 赛前共享资产（3 分钟，只列不分配）

**这一节是今晚最容易被跳过、但性价比最高的部分。**

理由：明天定选题后只剩 **10/22 晚 + 10/23 一整天**。如果今晚不预先准备"三个候选都用得上"的东西，明天定了就要从零开始。

| 资产 | 三个候选都用得上吗 | 什么时候做 |
|---|---|---|
| **材料模板**：按两条验收线原文各起一个小标题 + 「从 __ 到 __」占位 + 表格骨架 | ✅ 都用（AI 评审吃这个，见 §2 推论 1/5） | **今晚之后就能做，不用等选题** |
| **验证脚本框架**：断言 + 读数输出（"200 组输入，违反 0 例"这种句式） | ✅ 都用 | 同上 |
| **录屏流程**：录什么、录多长、怎么剪、设备检查清单 | ✅ 都用 | 同上 |
| **仓库协作底座**（门禁 / CI / 协作规范） | ✅ 已有 | 已完成 |
| 真实数据 / 素材 | ❌ 各不相同（菜单 / 玩法 / 会议录音） | 选题定了再做 |

⇒ **前四项今晚之后可以立刻开工，不等明天。** 这是把"明天才定选题"的损失压到最小的唯一办法。

## 7. 明天必须问清的 6 件事

按重要性排序，前三条直接决定我们怎么准备材料：

1. **AI 评审读什么？** 代码仓库 / 产品文档 / 演示视频 / 现场演示——四者的准备成本差一个量级。
2. **rubric 长什么样？** 是不是就是那 12 条验收线（6 赛道 × 2）逐条打分？有没有额外维度（创新性 / 完成度 / 技术难度）？
3. **有没有人工复核？** 纯 AI 评审 vs AI 初筛 + 人工终审，对"要不要讲情怀"的答案完全相反。
4. **6 个赛道是否全开？** 会不会某些赛道没人报就取消，或合并？
5. **提交截止时间与形式**（文件？链接？现场拷？）
6. **是否限制工具/模型**（有没有指定平台、有没有算力额度）。

## 8. 回滚路径与切换条件（今晚的决定怎么退回来）

**今晚的决定本身是可逆的**：只收敛方向、不写代码 ⇒ 反悔成本接近 0，没有沉没成本。这是刻意设计的——正因为明天权重未知，今晚才只做低承诺的决定。

| 时点 | 反悔成本 | 回滚做法 |
|---|---|---|
| 今晚 – 明天听完准则 | **0** | 方向写在纸上，改一行字即可 |
| 明天 – 23 日晚 | 低 | 赛前资产**按方向分目录隔离**（`prep/<方向>/`），切方向就换目录，不删不覆盖旧目录 |
| 24 日开赛后 | 高 | **不再切**。硬切等于交半成品 |

**切换触发条件**（出现哪条读数就切，不靠感觉）：

| 触发读数 | 切到哪 |
|---|---|
| 明天 rubric 里「创新性 / 技术难度」占比高 | 从「可机械证明」型（用餐 / 游戏）切向「故事型」（查证 / OPC） |
| rubric 明确就是那 12 条验收线逐条打分 | **保持**「可机械证明」型，不切 |
| 技能栈里没人能做前端 | 游戏出局（§4.0 的 C0） |
| 技能栈里没人愿意整理数据 | 用餐出局（§4.0 的 C0） |
| 队友里没人能做真实数据与验证 | 放弃「用餐」，改「游戏」（游戏不需要外部数据） |

## 10. 作废读数留痕（v1 的错误，别再用）

| # | v1 写的 | 实际情况 | 错在哪 |
|---|---|---|---|
| 1 | 「每队最多 4 人，5 人超限」 | **5 人已验证合规** | 把官方赛事规则套到校内赛上 |
| 2 | 「时间是 10/24–25 10:00–18:00」 | 校内赛时间**未知**，与官方站无关 | 同上 |
| 3 | 「评审含选手人气投票 ⇒ 抬高'3 秒看懂'权重」 | 校内赛**大概率是 AI 评审**，无证据有人气投票 | 推论的前提没了，推论作废 |
| 4 | 「每条赛道 3 个赛道之星，共 18 个」 | 校内赛奖项设置**未知** | 同上 |
| 5 | 「提交物是作品介绍+演示视频+截图+工具材料」 | 校内赛提交形式**未知**，明天才讲 | 同上 |
| 6 | §5 整节「5 人三方案（问主办方 / 拆 4+1 / 编外）」 | **整节作废** | 问题本身不存在 |

**仍然成立的**：`docs/03` §1 六赛道两条验收线（这是"套用"的部分）、§2 引擎复用判定（纯本地分析）、§3 三个候选的相对比较（除"人气投票"那一条论据）。

**教训**：看到"官方赛事页"就直接把它当本赛事的规则，是**把最像的来源当成最权威的来源**。下次先问一句"我们参加的是哪一场"。
