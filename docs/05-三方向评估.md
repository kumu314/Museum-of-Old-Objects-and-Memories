## 1. Hundun Lite 架构读数（解包 `app.asar`，非印象）

来源：`D:\Hundun Lite\resources\app.asar`（1.5 MB，124 个文件）。快捷方式指向 `D:\Hundun Lite\Hundun Lite.exe`。

| 层 | 内容 | 规模 |
|---|---|---|
| **主进程** `out/main/` | `index.js` 22K / `plugin-manager.js` 36K / `plugin-installer.js` 21K / `plugin-loader.js` 5.6K / `database.js` 7K / `plugin-preload.js` 9K / `mirror-manager.js` 4.2K / `paths.js` 6.6K / `platform-support.js` 3K / `sound-settings.js` 2.8K | 约 118 KB |
| **渲染层** `out/renderer/` | Vite 打包 `index-*.js` 299K + `index-*.css` 38K，依赖 **Vue 3 + Pinia + vue-router** | 约 340 KB |
| **4 个插件** | `task`（任务+截止+提醒）、`fast-txt`（Markdown 编辑器）、`fast-cmd`（命令面板）、`calculator` | 约 400 KB |
| **音效** | 8 个 mp3（click/error/OK/home/loading/setting/exit/change/bengbeng） | 约 200 KB |
| **技术栈** | Electron 28.3.3，MIT，`gitee.com/luofengwuqi`，定位「**复古掌机风格的桌面效率工具**」 | — |

### 插件机制（这是「扩展功能」成本的关键）

一个插件 = `manifest.json` + `main.html` + `js/` + `css/`。manifest 字段：

```json
{
  "id": "task", "name": "TASK", "icon": "📋", "color": "#ff0080",
  "entry": "main.html",
  "windowSize": { "width": 400, "height": 520 },
  "permissions": ["storage", "notifications"]
}
```

**每个插件自带一套完整基础设施**（看 `task` 插件的文件列表）：`sdk.js`（3K）、`i18n.js`（5.7K）+ `i18n-html.js`、`theme-sync.js`、`keyboard.js`（4.6K）、`toast.js`、`modal.js`、`app-state.js`、`events.js`、`render.js`、`form.js` / `tasks.js` / `reminders.js`。

⇒ **加一个新插件的边际成本不高**：基础设施已备好，新插件主要是业务逻辑 + 界面。有李同学在队里，成本更低。

### 已有的三个插件正好构成一条闭环

```
fast-txt（输入：粘贴/编辑文本）
   ↓
【缺一个：AI 处理插件】  ← 这就是要补的
   ↓
task（输出：待办 + 截止 + 通知提醒）
```

**这条链是本次评估里最硬的读数**：要补的恰好是中间那一环，两端都已存在且跑通。

## 2. 三个方向的验收线匹配度

### 2.1 逐条对照（验收线原文见 `docs/03` §1）

| 方向 | 赛道 | 验收线 A | 匹配 | 验收线 B | 匹配 |
|---|---|---|---|---|---|
| Hundun Lite 扩展 | 办公 | 真实任务：会前简报/会议待办/汇总周报，**选一件做好** | **强**。选「会议待办」，边界天然受限 | 交付能用：输入需求→完成任务→结果拿来就能用 | **强**。粘贴会议记录→待办清单→可直接勾选执行 |
| 记忆博物馆 | OPC | 找准客户：客户需求是什么 | **中**。用户画像（怀旧/家庭/老人）说得出来，但**没有真实客户证据** | 跑通交付：能用的产品+样例交付+讲清怎么收费 | **中**。能做出产品，收费模式要现编 |
| 聚餐剧本杀 | 游戏 | 一看就会玩：浏览器或手机直接玩 | **弱**。要"连同一个 agent"+分配身份+理解规则，**做不到一看就会** | 完整玩一局：开始、挑战、结算、玩完还能再来一局 | **弱**。剧本杀一局 30–60 分钟，现场演示不完；「结算」「重开」不是剧本杀的原生概念 |

⚠ **§2.1 最后一行是本次评估最重要的发现**：剧本杀这个形态，和游戏赛道的两条验收线**结构上不匹配**。
游戏赛道要的是「短、可重开、零学习成本」，剧本杀要的是「长、一次性、沉浸叙事」。这不是实现问题，是形态问题。

**修正方向（不必放弃剧本杀）**：把「剧本杀」改成「**一局 3–5 分钟的可重开派对游戏**」——保留身份分配和 AI 叙事，但砍到能「再来一局」的粒度。**改了才进游戏赛道。**

### 2.2 门槛 G1/G2/G3 + 前置 C0

| 方向 | C0（有人能独立做） | G1（验收线一句话命中） | G2（「从 __ 到 __」） | G3（异常路径） |
|---|---|---|---|---|
| Hundun Lite 扩展 | ✅ **李同学是原作者**（最强） | ✅ 过 | ✅ 「粘贴 2000 字会议记录 → 40 秒出 12 条待办，人工整理需 25 分钟」 | ✅ 空输入/超长输入/无待办的闲聊 |
| 记忆博物馆 | ✅ 王同学 | ✅ 过 | 🟡 「拍 1 张照片写 3 句话 → 30 秒生成一条可检索展品」 | ✅ 无图/描述为空/重复提交 |
| 聚餐剧本杀 | ✅ 用户自己 | 🟡 **需先改形态**（§2.1） | 🟡 「组一局从拉群找人 30 分钟 → 扫码即玩 30 秒」 | 🟡 掉线重连/人数不足 |

## 4. 我的推荐：Hundun Lite 扩展，加一个「会议待办」插件

**具体做什么**（不是泛泛的"扩展功能"）：

> 新增第三个插件 `meeting-todo`：粘贴一段会议记录（或上传转写文本）→ AI 抽取「谁 · 在什么时候前 · 做什么」→ 一键写入 `task` 插件并设提醒。

**为什么是这个而不是别的功能**：

1. **正好补上 §1 那条闭环的中间环**，两端（fast-txt / task）都已跑通，不用重造。
2. 办公赛道**明确给了三选一**（会前简报 / 会议待办 / 汇总周报），选「会议待办」边界天然受限，不用自己找范围。
3. 「交付能用」可以用**真实会议记录**当场验证，证据链最短。
4. 复古掌机风格 + 已有 4 个插件 = 演示时有视觉记忆点，也有的可讲（插件机制）。

**「从 __ 到 __」**（AI 评审吃这句）：粘贴 2000 字会议记录 → 40 秒出 12 条结构化待办，人工逐条整理需约 25 分钟。

**必须解决的三个问题**（不是技术问题，但会翻车）：

| # | 问题 | 为什么要现在说 |
|---|---|---|
| 1 | **作品归属**：Hundun Lite 是李同学的个人项目（gitee.com/luofengwuqi）。比赛作品算团队作品还是他的个人项目？ | 答辩时评委可能问"哪些是你做的"。**现在不说清，比技术问题更容易翻车** |
| 2 | **AI API 从哪来**：key、额度、现场网络。三条里唯一有不可控外部依赖的 | 比赛当天没网就废。要么申请额度，要么准备离线降级方案 |
| 3 | **同质化**：「AI 会议总结」是最挤的方向 | 差异化只能靠「结果真的能用」（精确到人+时间+可勾选+进已有提醒系统），否则就是又一个总结器 |

## 5. 一个可能比排序更值钱的洞察：Hundun Lite 可以当三个方向的共同底座

它是插件化架构 ⇒ **方向一和方向三都可以做成 Hundun Lite 的插件**：

| 方案 | 做法 | 好处 | 代价 |
|---|---|---|---|
| **A. 只做会议待办插件** | 在 Hundun Lite 上加 `meeting-todo` | 最稳，工作量最小 | 只有一个亮点 |
| **B. Hundun Lite + 两个插件** | 再加一个「记忆博物馆」或「一局式派对游戏」插件 | **一次解决两个方向的取舍**；演示时一个软件里两个彩蛋 | 工作量 ×1.6；插件窗口尺寸受限（400×520 / 800×540） |
| C. 三个方向各自独立做 | 不用 Hundun Lite | 作品独立性最清晰 | 工作量 ×3，时间不够 |

**方案 B 值得认真考虑**：它把「选 A 还是选 C」这个二选一，变成「用 Hundun Lite 当底座，把另一个方向做成插件」。
赛道报**办公**（因为底座是效率工具），但演示时能亮出第二个插件——既满足验收线，又保住另一个方向的创意。

⚠ 代价：插件窗口尺寸是 manifest 里写死的（`windowSize`），复杂界面可能挤。记忆博物馆这种画廊式 UI 更适合 800×540 那个档位。

### 6.1 维持现状基线（不选的代价）

**维持现状（今晚不拍板）是合法选项**，但它的有效期到今天为止：

- 现在 10-22 16:30，比赛 10-24，距开赛约 1.5 天。不拍的代价是三个方向都不启动 ⇒ 10-23 全天空转 ⇒ 上场时手上只有原封不动的底座，**把 1.5 天赛前产能归零**。
- 但反过来说，**现状还能撑的部分比另外两个方向多**：Hundun Lite 本身已是一个能演示的成品（4 个插件跑通、可安装、有视觉风格）。就算不加任何功能，它也是"完整可用的桌面工具"。
- ⇒ 维持现状的真实代价**不是"零产出"，是"放弃把一个已有成品变成参赛作品的机会"**。这是三个方向里唯一「不做事也有东西可演示」的选项，也是它在时间不够时最抗打的原因。

### 6.2 备选路线（主推荐不可行时走哪条）

| 主推荐失效的原因 | 备选路线 | 代价 |
|---|---|---|
| 作品归属谈不拢（§4 问题 1） | 不用 Hundun Lite，三个方向各自独立做 | 工作量 ×3，时间不够 ⇒ 实际只能退到「记忆博物馆」（人时 22–28） |
| 李同学的代码改不动 / 没人读得懂 | 只做前端 mock + 后端 CLI 交付，**放弃 Electron 打包** | 丢掉"桌面软件"的形态优势，退回 Web 应用，和另外两个方向同质 |
| AI API 额度拿不到 | 降级为**本地规则引擎**（正则 + 关键词表） | 演示仍能跑，验收线 B 的证据从"AI 抽取"变成"200 组测试 0 违反"，创新性叙事变弱 |
| 时间不够（最可能） | 砍到**只做「粘贴 → 待办」单链路** | 砍掉通知、日历导出、UI 打磨、第二个插件（§5 方案 B 降级为方案 A） |
| 评分准则重"原创性/从零开始" | 切「记忆博物馆」（§6 触发条件第一条） | 从零做 4 个模块，赛前只能完成约 40% |

**判断**：备选路线里最可能被触发的是「时间不够」。所以**一上来就该按单链路范围做**，把 §5 方案 B 当 bonus 而不是基线——这样即使最后只完成单链路，交付也是完整的。
