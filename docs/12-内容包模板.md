# 内容包模板与素材缺口（E 主责）

> **依据**：`docs/PROJECT_PLAN.md` v0.6 §5.3 样例与模型、§9.5 分享与素材、§9.7 上传格式与限额、§6 AI 和故事如何配合；`docs/TEAM_EXECUTION_PLAN.md` §3.5 E 的负责内容与第一个交付物。
> **版本说明**：已按开发书 v0.6（2026-10-23）校对，字段与限额未变（图片 10 MiB、音频 20 MiB、各轴不超过 8192 像素且总像素不超过 32,000,000）。
> **硬约束**：内容缺失时**明确列出缺失项**，不由 AI 补造。不虚构演示故事、年份、人物关系与情绪；不确定处保留「约」「可能」「记不清」原话。

---

## 1. 一个内容包要装什么

一件展品 = 一个内容包。字段分三段：**事实层**（物主给的原始材料，不许改写）、**整理层**（AI 与人工的展签草稿，可迭代）、**确认层**（物主确认的版本记录）。

### 1.1 事实层（原始材料，只增不改）

| 字段 | 必填 | 说明 |
|---|---|---|
| 展品编号 | ✅ | 建议 `EX-01` 形式，全项目唯一 |
| 展品名称 | ✅ | 用物主自己的叫法，不用我们起的雅名 |
| 约略年代 | ✅ | 允许「八十年代末」「不记得哪年，小时候」。**禁止补成精确年份** |
| 类别 | ✅ | 立体重点 / 简单立体 / 照片或票据（§5.3 三件样例的分配依据） |
| 原始讲述 | ✅ | 物主原话，逐字记录，不改写、不润色、不合并 |
| 讲述来源 | ✅ | 谁讲的、什么时候、通过什么渠道（当面/微信语音/文字） |
| 来源片段标识 | ✅ | 展签里每一句要能指回原始讲述的哪一段，用于 AI 草稿的来源标注 |
| 照片 | ✅ | 原图不裁剪、不压缩、不转格式；另存处理版 |
| 原声 | ⬜ | 可选。若提供，需单独标注许可范围 |
| 录音整理文本 | ⬜ | 若有录音，转写稿单独记（对应工程 `transcript`）。**不能与原始讲述混为一栏**，两者来源不同 |
| 物主已知的疑点 | ⬜ | 物主自己说"记不清""可能是"的地方，**必须保留**，不能删 |

### 1.2 整理层（草稿，可迭代）

| 字段 | 必填 | 说明 |
|---|---|---|
| AI 草稿 | ⬜ | 由 AI 生成，必须带来源片段标识；生成时间与所用模型记下 |
| 人工修改记录 | ⬜ | 谁改了什么，为什么改。改掉事实性内容要写理由 |
| 追问清单 | ⬜ | 最多两个待问物主的问题（§6 限制） |
| 当前展签 | ✅ | 待确认的最终文本。事实与整理必须可区分，读者能看出哪句是原话 |

### 1.3 确认层（版本记录，不可变）

| 字段 | 必填 | 说明 |
|---|---|---|
| 确认版本号 | ✅ | 对应系统里的展签版本；改内容即失效 |
| 确认人 | ✅ | 物主本人（线下/微信确认也算），由制作人员在系统内代为操作 |
| 确认时间与渠道 | ✅ | 例：10 月 24 日 20:15 微信语音 |
| 确认范围 | ✅ | 确认了哪几句、哪些照片可以公开 |
| 公开范围 | ✅ | 可公开 / 仅限家人 / 不可公开。默认最保守 |

### 1.4 素材许可（每个文件单独记）

| 字段 | 说明 |
|---|---|
| 文件标识 | 文件名或哈希，确保能对上具体文件 |
| 来源 | 物主提供 / 公共馆藏（如 Smithsonian CC0）/ 开源模型库 |
| 许可范围 | 可用于演示 / 可公开分享 / 仅内部验收 |
| 授权人 | 谁给的许可，什么时候 |
| 近似程度 | 若用近似模型或提前制作的模型，**如实标注**（§2.3 分工要求） |

## 3. 三件样例的素材缺口

`TEAM_EXECUTION_PLAN` §2.3 定的是：六格展柜、三件完整样例——一件重点立体、一件简单立体、一件照片或票据，至少一件有获准使用、能播放的原声。

| 样例 | 类型 | 需要什么 | 现在有没有 | 卡在哪 |
|---|---|---|---|---|
| S1 | 立体重点 | 一件形态较规则、无强反光的旧物；6 至 10 张多角度照片，或一个现成可用模型 | ❌ 无 | 需物主提供实物与照片；模型来源待定 |
| S2 | 简单立体 | 几何感强的旧物（盒、杯、书一类） | ❌ 无 | 同上 |
| S3 | 照片或票据 | 一张清晰的正面照，背面若有字也拍 | ❌ 无 | 需物主授权公开 |
| S4 | 原声 | 一段获准使用的录音，手机录亦可，能听清 | ❌ 无 | 需物主同意录音公开 |

候选物是相机、磁带、车票（§2.3），但最终按真实可用素材定。**难以取得合格模型时，替换为形态更易实现的旧物**，保留真实 3D 主体验——不要为了凑"相机"去用近似模型硬撑。

## 5. 与工程契约的字段映射（2026-10-24 核对 `src/contracts/`）

本模板是**收素材时人填的工作单**，工程契约是**入库 schema**，两者不必逐字相同，但必须能对上，否则 E 收完素材往系统里填要现场翻译。下表按 `src/contracts/museum.ts`、`src/contracts/ai.ts`、`src/contracts/primitives.ts` 实读结果逐条核对。

| 模板字段 | 工程契约 | 落地情况 |
|---|---|---|
| 展品编号 | 无输入字段（`id` 系统生成） | 模板编号仅作人工标识，需另记系统 id 对照 |
| 展品名称 | `name`（`exhibitNameSchema`） | ✅ |
| 约略年代 | `era`（1–80 字） | ✅ 允许「约八十年代末」，与"禁止补成精确年份"不冲突 |
| 类别（立体重点 / 简单立体 / 照片票据） | `modelKey`（`camera-01` / `cassette` / `ticket` / `photo-plane`）+ `slotIndex`（0–5） | ⚠️ **语义不同**：工程按模型资源分，不按内容难度分；需人工决定每件用哪个 `modelKey` |
| 原始讲述 | `rawStory`（≤12,000 字） | ✅ |
| ——（模板无此字段） | `transcript`（录音整理文本，≤12,000 字，可空） | ⚠️ **模板缺**：录音转写要单独留一栏，不能和 `rawStory` 混 |
| 讲述来源（谁 / 何时 / 渠道） | 无字段 | ❌ **未落地** |
| 来源片段标识 | `sourceSegments`（≤40 条，每条 ≤6,000 字；每条含 `id`、`source`（`rawStory` / `transcript`）、`text`） | ⚠️ 工程多 `source` 归属；模板的片段要标清出自讲述还是转写 |
| 照片 | `photoAssetId`（素材表引用） | ✅ 走上传流程 |
| 原声 | `audioAssetId` | ✅ 走上传流程 |
| 物主已知的疑点 | 无独立字段（只能保留在 `rawStory` / `transcript` 原文里） | ❌ **未落地** |
| AI 草稿 | `aiDraft`（`output.caption`、`output.questions` ≤2、`output.sourceSegmentIds`、`sourceVersion`） | ✅ |
| 人工修改记录 | 无字段 | ❌ **未落地**（AI 草稿到确认展签之间的改动过程没有留痕） |
| 追问清单 | `output.questions`（≤2） | ✅ 与 §6 上限一致 |
| 当前展签 | `caption`（0–120 字） | ⚠️ **限 120 字**，模板要按这个长度写 |
| 确认版本号 | `confirmedVersion` | ✅ |
| 确认人 | 无独立字段（只有 `confirmationNote` 1–2,000 字自由文本） | ⚠️ 压成文本 |
| 确认时间与渠道 | `confirmedAt` 有时间；**渠道无字段** | ⚠️ 渠道只能写进 `confirmationNote` |
| 确认范围 | `confirmationNote` | ⚠️ 压成文本 |
| 公开范围（可公开 / 仅限家人 / 不可公开） | 无字段 | ❌ **未落地**：工程只有展馆级 `shareEnabled` 布尔，没有单件或单素材的可见性 |
| 素材许可（文件 / 来源 / 许可范围 / 授权人 / 时间） | `sourceNotice`（≤1,000 字）+ `approximation`（≤500 字） | ⚠️ **部分**：许可范围、授权人、授权时间无字段，只能并进 `sourceNotice` 文字 |

**四条未落地项的实际后果**：讲述来源、已知疑点、人工修改记录、公开范围，这四项在开发书 §5、§6 里是"AI 不能自动确认"和"来源可追溯"的支撑，但工程目前没有对应字段，只能以自由文本形式塞进相邻字段。要补，属于契约变更（C 与 B 主责，需协调）；不补，演示时只能用文字声明说明这些信息存在别处，AI 评委若追查来源链，拿不出结构化证据。

**一处硬约束**：`modelKey` 只有 4 个取值，六格展柜里的每件展品都必须落在 `camera-01`、`cassette`、`ticket`、`photo-plane` 之一。真实旧物若不是相机、磁带、票据，当前工程**塞不进去**，要么新增模型 key（改契约与 A 的资产清单），要么改用 `photo-plane` 当平面展示。这直接约束 §3 三件样例的选品——选品时先确认能落进这 4 个 key。

## 6. 已知缺口

1. **一个内容包都没有**——没有物主、没有素材，第 2 节模板全是空的。
2. **物主未定**——这是 E 的第 1 个前置，也是全队 G2 的起点。它不解，A 拿不到真实模型、B 没真实数据可录。
3. **许可范围无标准文本**——目前只有"可公开/仅限家人/不可公开"三档，物主口头同意算不算数，需要和 C 的确认规则对齐；且第 5 节已查明这三档在工程里没有对应字段。
4. **原声许可与上传限额要对齐**——v0.6 §9.7 规定音频上限 20 MiB、允许 MP3/M4A(AAC)/WAV(PCM)；物主给的录音如果是其他编码，要么先转码（转码要留原始文件），要么明确告诉物主不能用。
5. **模板与契约有 8 处不对应**——详见第 5 节，其中 4 处是工程未落地字段、1 处是模型 key 硬约束。
