## 工具链与配置

固定 Node.js **26.12.0**、pnpm **12.14.0**、PostgreSQL **18.6**。直接依赖精确版本见 `package.json`，完整依赖树见 `pnpm-lock.yaml`；三维预览使用同一工程内的 Vite。音频校验需要系统 `ffmpeg` / `ffprobe`，CI 已安装。

```sh
pnpm install --frozen-lockfile
pnpm db:local
pnpm db:migrate
pnpm db:migrate:test
pnpm dev
# 另一个终端启动独立三维原型
pnpm dev:scene
```

`db:local` 需要 Docker Compose，创建开发与测试两个 PostgreSQL 容器及各自持久卷，端口为 15432 / 15433。保留已有 `.env.local`；首次运行生成私密配置与 `.local/uploads`。应用账号无超级用户、创建库或创建角色权限，两个容器使用不同凭据。不要使用 `docker compose down -v` 删除数据。

应用地址为 `http://127.0.0.1:17682/`，三维原型为 `http://127.0.0.1:17681/`。启动前检查端口占用。`/api/health` 核对当前源码要求的完整迁移序列、文件名与校验和，并检查上传目录可读写；缺迁移或历史不一致时返回失败，不会自动执行或修复迁移。

外置 PostgreSQL 时，依据 `.env.example` 创建 `.env.local`，不覆盖已有配置。`DATABASE_URL` 与 `TEST_DATABASE_URL` 必须指向隔离数据库；`UPLOAD_DIR` 为 `public` 之外、应用账号可读写的绝对路径；`SESSION_PASSWORD` 至少 32 个随机字符。真实配置、凭据、数据库和素材均不得进入 Git。

停止本地数据库但保留数据：

```sh
docker compose -f compose.local.yml stop
```

## 账号与归属

方案 B 的账号接入方式是**用户名+密码自助注册**，个人归属隔离同批落地：每个账号只能访问自己创建的展馆。

- **自助注册**：`POST /api/auth/register`，请求体 `{ username, password }`。用户名 3–40 个字符且不含空白，密码 12–256 个字符。注册成功直接建立会话并返回账号信息，用户不必再登录一次。用户名唯一性由数据库唯一约束裁决，并发注册同一名字只有一方成功。默认每个用户名五分钟最多十次注册尝试。
- **自助注册开关**：默认开启；生产临时关闭设 `SELF_REGISTRATION=closed`，此时接口返回 `FORBIDDEN`。该开关只影响注册入口，不影响归属与权限判断。
- **管理员开通**：将 `TEAM_USERNAME` 和至少 12 字符的随机 `TEAM_PASSWORD` 写入私有 `.env.local`，运行 `pnpm team:create`，随后移除明文密码配置。脚本不覆盖同名账号，也不打印密码。加 `TEAM_ROLE=user` 可开通标记为普通用户的账号；该标记不影响权限。

不存在或未启用的账号共享单进程五分钟十次慢哈希预算，超过后直接返回现有登录限流错误，不保存任意用户名；已知有效账号继续使用各自的数据库计数，不受此预算耗尽影响。这项保护适用于当前单实例部署，进程重启会重置，不能替代部署入口的流量限制或作为多实例统一限流。

展品创建和更新的 JSON 请求上限为 512 KiB，容纳契约允许的原文、来源片段及 Unicode 转义；其余 JSON 入口仍为 64 KiB。业务字数、片段数量与权限校验保持原约束。

**归属规则**：`museums.created_by` 是展馆归属的唯一权威字段，迁移 `0003_user_ownership.sql` 给它加了工作台列表用的部分索引，并用触发器锁定归属在创建后不可更改。因此：

- 工作台列表只返回本人展馆。
- 访问他人展馆的读、写、加展品、发布、换链与素材请求一律返回 `NOT_FOUND`，与展馆不存在不可区分。
- 升级到该迁移后，原有团队账号不再共享全部展馆，各自只看到自己创建的馆。这是方案 B 要求的行为变化，不是数据丢失。
- `team_members.role` 只是账号来源标记（`member` 管理员开通 / `user` 自助注册），**不参与任何授权判断**；授权一律只看归属字段。

注册与登录都使用 iron-session 加密 cookie 与数据库会话记录，8 小时过期，退出后会话撤销；写请求校验 Origin，生产 cookie 只经 HTTPS 发送。每账号五分钟最多十次登录尝试。

注册即登录时会撤销当前 cookie 对应的旧会话；账号、会话替换及注册计数清理在同一数据库事务中完成。分享数据和素材 API 同样要求有效登录，未登录或会话撤销后返回 401 `UNAUTHORIZED`，不返回内容。已登录的非所有者可以凭有效链接读取当前快照，但不能读取私有草稿或进行制作操作。正式参观页面已接入相同的会话检查：未登录转到登录页，登录后返回原有效分享路径；会话失效时重新登录。

登录与注册的节流计数按用途分区存放（`login_attempts(scope, username)`，见 `0004_login_attempt_scope.sql`），两组计数器互不影响：注册被节流不会锁住同名账号的登录，反过来也一样。这条约束由数据库主键保证，不依赖用户名允许哪些字符——早期用字符串前缀做命名空间，含冒号的用户名会与另一个账号的键撞在一起。

## 检查与浏览器、HTTP 回归

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm test:db
pnpm test:scene
pnpm exec playwright install chromium
pnpm test:browser
pnpm test:http
pnpm build:scene
APP_ORIGIN=https://museum.example.test pnpm build
# 仓库规范与应用检查；浏览器和 HTTP 回归在 CI 中各列一步
APP_ORIGIN=https://museum.example.test bash scripts/check.sh
```

- `test`：契约、配置、素材处理与 AI 适配边界。
- `test:db`：使用 `TEST_DATABASE_URL` 的实际 PostgreSQL，检查迁移、约束、事务、快照、撤销与 AI 来源版本。
- `test:scene`：独立场景的纯逻辑测试，不能替代浏览器视觉验收。
- `test:browser`：启动回环随机端口的 Vite 页面，在 Chromium 中运行真实工作台、自传和共同作者组件，覆盖模型恢复与编辑保护、提交中锁定及失败保留、章节刷新冲突等回归。API 使用合成响应，拒绝外部网络，不读取数据库或真实 AI 配置；Next 导航、图片和 WebGL 绘制由测试适配替换，不等同完整应用端到端或 3D 视觉验收。首次运行需安装 Chromium；Linux CI 使用 `pnpm exec playwright install --with-deps chromium`，本机也可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/google-chrome-stable pnpm test:browser` 指定已安装的 Chrome。进程结束时关闭浏览器和测试服务。
- `test:browser` 中的 `model-loading.test.mjs` 使用真实 WebGL 展柜与合成 GLB，验证资料刷新、同页换格无重复下载，以及检视、替换、失败回退、重试和翻页。其余界面回归仍按各自适配边界运行；该用例需要浏览器支持 WebGL。
- `test:http`：执行 `tests/e2e/api-core.test.ts`、`assets-http.test.ts`、`ownership-http.test.ts`、`registration-http.test.ts`、`share-access.test.ts`、`owner-museum.test.ts`、`direction1-http.test.ts` 与 `memoir-http.test.ts`。需先运行 `pnpm db:local`；仅使用本项目 15433 端口的 Compose 测试容器，在容器内创建本次专用临时数据库，运行迁移并创建两个随机密码的测试账号（`http-regression` 与 `http-regression-other`，后者用于归属隔离），注册用例再自行注册账号。应用源码副本、Next 开发缓存与上传文件放在私有 `.local/http-regression-*`，独立进程使用自动分配的回环端口。健康检查后，在独立限时准备阶段请求未登录的展馆列表与分享页，确认 401 与登录跳转，完成冷编译，再运行保持原请求超时及断言的回归；失败只报告脱敏路由。结束时停止该进程并移除本次数据库和临时文件，保留 `server.log` 供诊断；不清空开发库、常规测试库或原上传目录，不连接真实 AI。

CI 运行冻结锁安装、实际 PostgreSQL 迁移、类型检查、lint、契约/服务端/实库/场景测试、两种生产构建、浏览器组件回归和 HTTP 回归。HTTP 回归验证实际路由、会话与文件读写，但使用 Next 开发服务器，不替代生产部署或完整浏览器端到端验收。

### 正式参观页：当前操作与历史接入记录

工作台先保存展馆和展品，记录对当前版本的人工确认，再点击“发布整座展馆”生成快照。成功后可点击醒目的“进入展馆”打开 `/museum/published`，馆主仅凭自己的登录会话即可查看已发布版本，展馆保持私密时也可使用；刷新工作台后此入口仍在发布面板中。这里读取已封存的发布快照，后续草稿修改不会改变展示内容，再次发布才更新；原 `/museum` 仍用于当前草稿预览。首次发布后需另点“开启持链接访问”并确认，才会返回可打开或复制的访客参观链接；已开启访问时，后续发布更新快照并保留原链接。服务端仅保存 token 摘要，重新打开工作台不能取回原链接；需要时点击“更换参观链接”，确认旧链接失效后生成新链接。“停止分享并设为私密”使页面、数据与私有素材的新请求失效，再次发布不会自动重新开放，且不能撤回已下载副本。

个人自传入口位于未建馆页面、展品工作台以及本人展馆页面顶部，链接到 `/memoir`。自传可独立创建并选择“暂不关联”，无需先创建展馆；需要把单独授权的章节用于展馆展示时，才选择关联展馆。当前在线自传仍只对服务端登记的合成资料演示账号开放，增加导航入口不会解除该限制。离开工作台前如有未保存输入，需先确认是否放弃。

`/share/[token]` 每次请求先检查用户会话，再读取当前公开快照；未登录转到登录页，登录后返回原有效分享路径，使用独立错误页统一处理无效和已撤销链接，不公开内部讲述或 AI 草稿。页面使用动态渲染及 `no-store`，实拍通过分享素材接口直接读取，不经过图片优化缓存。页面隐藏后重新显示或从往返缓存恢复时重新核对 token 和快照；已加载的内容不承诺即时撤回。开发日志排除分享及登录续访请求，分享页与登录页均设置 `Referrer-Policy: no-referrer`；部署时反向代理访问日志也须排除或遮蔽 token（包含登录续访的 `next` 查询参数）。
