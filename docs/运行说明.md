更新：2026-10-24。应用、三维原型、测试与文档统一在 `heikesong`，共用根目录锁文件。最终目标已改为方案 B 加自动建模；本页命令仍描述当前团队制作基础，不能当作用户自助或三维生成已可运行。

## 工具链与配置

固定 Node.js **26.12.0**、pnpm **12.14.0**、PostgreSQL **18.6**。直接依赖精确版本见 `package.json`，完整依赖树见 `pnpm-lock.yaml`；三维预览使用同一工程内的 Vite。音频校验需要系统 `ffmpeg` / `ffprobe`，CI 已安装。

```sh
pnpm install --frozen-lockfile
pnpm db:local
pnpm db:migrate
pnpm db:migrate:test
pnpm dev
# 另一个终端启动独立三维原型
pnpm dev:scene
```

`db:local` 需要 Docker Compose，创建开发与测试两个 PostgreSQL 容器及各自持久卷，端口为 15432 / 15433。保留已有 `.env.local`；首次运行生成私密配置与 `.local/uploads`。应用账号无超级用户、创建库或创建角色权限，两个容器使用不同凭据。不要使用 `docker compose down -v` 删除数据。

应用地址为 `http://127.0.0.1:17682/`，三维原型为 `http://127.0.0.1:17681/`。启动前检查端口占用。`/api/health` 校验数据库迁移记录及上传目录可读写。

外置 PostgreSQL 时，依据 `.env.example` 创建 `.env.local`，不覆盖已有配置。`DATABASE_URL` 与 `TEST_DATABASE_URL` 必须指向隔离数据库；`UPLOAD_DIR` 为 `public` 之外、应用账号可读写的绝对路径；`SESSION_PASSWORD` 至少 32 个随机字符。真实配置、凭据、数据库和素材均不得进入 Git。

停止本地数据库但保留数据：

```sh
docker compose -f compose.local.yml stop
```

## 账号与归属

方案 B 的账号接入方式是**用户名+密码自助注册**，个人归属隔离同批落地：每个账号只能访问自己创建的展馆。

- **自助注册**：`POST /api/auth/register`，请求体 `{ username, password }`。用户名 3–40 个字符且不含空白，密码 12–256 个字符。注册成功直接建立会话并返回账号信息，用户不必再登录一次。用户名唯一性由数据库唯一约束裁决，并发注册同一名字只有一方成功。默认每个用户名五分钟最多十次注册尝试。
- **自助注册开关**：默认开启；生产临时关闭设 `SELF_REGISTRATION=closed`，此时接口返回 `FORBIDDEN`。该开关只影响注册入口，不影响归属与权限判断。
- **管理员开通**：将 `TEAM_USERNAME` 和至少 12 字符的随机 `TEAM_PASSWORD` 写入私有 `.env.local`，运行 `pnpm team:create`，随后移除明文密码配置。脚本不覆盖同名账号，也不打印密码。加 `TEAM_ROLE=user` 可开通标记为普通用户的账号；该标记不影响权限。

**归属规则**：`museums.created_by` 是展馆归属的唯一权威字段，迁移 `0003_user_ownership.sql` 给它加了工作台列表用的部分索引，并用触发器锁定归属在创建后不可更改。因此：

- 工作台列表只返回本人展馆。
- 访问他人展馆的读、写、加展品、发布、换链与素材请求一律返回 `NOT_FOUND`，与展馆不存在不可区分。
- 升级到该迁移后，原有团队账号不再共享全部展馆，各自只看到自己创建的馆。这是方案 B 要求的行为变化，不是数据丢失。
- `team_members.role` 只是账号来源标记（`member` 管理员开通 / `user` 自助注册），**不参与任何授权判断**；授权一律只看归属字段。

注册与登录都使用 iron-session 加密 cookie 与数据库会话记录，8 小时过期，退出后会话撤销；写请求校验 Origin，生产 cookie 只经 HTTPS 发送。每账号五分钟最多十次登录尝试。

注册即登录时会撤销当前 cookie 对应的旧会话；账号、会话替换及注册计数清理在同一数据库事务中完成。分享数据和素材 API 同样要求有效登录，未登录或会话撤销后返回 401 `UNAUTHORIZED`，不返回内容。已登录的非所有者可以凭有效链接读取当前快照，但不能读取私有草稿或进行制作操作。正式参观页面及其登录后返回原链接流程仍待接入验收。

登录与注册的节流计数按用途分区存放（`login_attempts(scope, username)`，见 `0004_login_attempt_scope.sql`），两组计数器互不影响：注册被节流不会锁住同名账号的登录，反过来也一样。这条约束由数据库主键保证，不依赖用户名允许哪些字符——早期用字符串前缀做命名空间，含冒号的用户名会与另一个账号的键撞在一起。

## 检查与 HTTP 回归

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm test:db
pnpm test:scene
pnpm test:http
pnpm build:scene
APP_ORIGIN=https://museum.example.test pnpm build
# 仓库规范与应用检查；HTTP 回归在 CI 中另列一步
APP_ORIGIN=https://museum.example.test bash scripts/check.sh
```

- `test`：契约、配置、素材处理与 AI 适配边界。
- `test:db`：使用 `TEST_DATABASE_URL` 的实际 PostgreSQL，检查迁移、约束、事务、快照、撤销与 AI 来源版本。
- `test:scene`：独立场景的纯逻辑测试，不能替代浏览器视觉验收。
- `test:http`：执行 `tests/e2e/api-core.test.ts`、`assets-http.test.ts`、`ownership-http.test.ts` 与 `registration-http.test.ts`。需先运行 `pnpm db:local`；仅使用本项目 15433 端口的 Compose 测试容器，在容器内创建本次专用临时数据库，运行迁移并创建两个随机密码的测试账号（`http-regression` 与 `http-regression-other`，后者用于归属隔离），注册用例再自行注册账号。应用源码副本、Next 开发缓存与上传文件放在私有 `.local/http-regression-*`，独立进程使用自动分配的回环端口。结束时停止该进程并移除本次数据库和临时文件，保留 `server.log` 供诊断；不清空开发库、常规测试库或原上传目录，不连接真实 AI。

CI 运行冻结锁安装、实际 PostgreSQL 迁移、类型检查、lint、契约/服务端/实库/场景测试、两种生产构建和 HTTP 回归。HTTP 回归验证实际路由、会话与文件读写，但使用 Next 开发服务器，不替代生产部署或完整浏览器端到端验收。

## 迁移与部署边界

SQL 入口为 `scripts/migrate.ts` 与 `src/server/db/migrate.ts`，从 `0001` 连续编号；迁移使用事务、数据库锁及 SHA-256 校验。已应用文件不重写，失败回滚，不使用清库或改校验和解决错误。

**迁移编号登记**：并行分支各自占用同一编号会被迁移器直接拒绝。开工前在下表登记，后合的一方按合并时的实际顺序协调编号。已应用的迁移既不改内容也不改编号，后续变化新增迁移；仅尚未应用的分支迁移可在协调后重编号。不得修改已应用记录或校验和来掩盖冲突。

| 编号 | 内容 | 状态 |
|---|---|---|
| `0001`—`0002` | 初始 schema、会话与登录节流表 | 已合入 `main` |
| `0003` | 展馆归属、账号来源标记、归属不可改触发器 | PR #11 |
| `0004` | 登录与注册的节流计数分区 | PR #11 |
| `0005` | 账号表改名为 `users`、会话表改名为 `user_sessions` | 预留给 #9，合入时取用 |
| `0006` 起 | 生成任务 | 未开分支 |

同一实体的 schema 变更由 C 统筹，并行分支不要各自写改同一张表的迁移，否则会同时留下两套账号与归属实现。账号表的最终名称为 `users`；改名本身放在连续迁移里完成，不在代码层用视图或别名掩盖。

首版按单实例 Node + 独立 PostgreSQL + 持久私有上传目录部署，生产 `APP_ORIGIN` 必须为实际 HTTPS 域名，由反向代理终止 TLS。应用入口是 `pnpm build` / `pnpm start`。完整部署说明、配套备份恢复脚本及恢复演练仍待完成，不能把构建通过当作已上线。

真实 AI、实际手机、正式参观页、完整浏览器 E2E 与生产部署尚未验收。AI 未配置时明确失败，不返回假生成内容。
