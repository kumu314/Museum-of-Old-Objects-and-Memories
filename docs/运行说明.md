# 运行说明（G0 工程基线）

更新日期：2026年10月23日\
适用：本仓库当前 `main` 的应用工程骨架。产品功能尚未实现。

## 一、版本基线

版本全部精确写入 `package.json`（`.npmrc` 已设 `save-exact=true`），不使用 `^` 或 `~`。升级由 C 统一发起并重生成锁文件。

| 项目 | 版本 | 说明 |
| --- | --- | --- |
| Node.js | 22.22.2 | 记录在 `.node-version`，CI 与本地共用 |
| pnpm | 10.30.3 | 记录在 `package.json` 的 `packageManager` |
| Next.js | 16.4.2 | App Router；Turbopack 为默认构建器 |
| React / React DOM | 19.3.1 | 不写 `^19`：`@react-three/fiber` 的上界是 `<19.4` |
| TypeScript | 5.9.3 | 不用 7.0.2：`typescript-eslint` 的 peer 上限是 `<6.1.0` |
| Tailwind CSS | 4.3.3 | 走 `@tailwindcss/postcss`，无 `tailwind.config.js` |
| Zod | 4.6.7 | 契约与配置校验 |
| pg | 8.23.1 | PostgreSQL 驱动，手写 SQL，不用 ORM |
| three / @types/three | 0.185.1 / 0.185.4 | 版本已锁定，由 A 的三维 PR 安装；本骨架不引入三维依赖 |
| @react-three/fiber / drei | 9.8.2 / 10.7.9 | 同上；R3F 9 是唯一支持 React 19 的大版本 |
| Vitest | 5.0.5 | 要求 Node ≥22.12，这是 CI 从 Node 20 升级的原因 |
| ESLint / typescript-eslint | 10.13.0 / 8.72.0 | `next lint` 在 Next 16 已移除，统一用 `eslint` CLI |

## 二、首次安装

```sh
# 1. 装依赖（严格按锁文件）
pnpm install --frozen-lockfile

# 2. 装提交钩子（每个 checkout 一次）
bash scripts/install-hooks.sh
```

pnpm 10 默认不执行依赖的构建脚本，需要构建的依赖列在 `pnpm-workspace.yaml` 的 `onlyBuiltDependencies` 里。新增原生依赖时补进去，否则运行期才报错。

## 三、检查与启动

```sh
pnpm run dev         # 开发服务器，默认 http://localhost:3000
pnpm run typecheck   # tsc --noEmit
pnpm run lint        # eslint .
pnpm run test        # vitest run
pnpm run build       # 生产构建
pnpm run check       # typecheck + lint + test
bash scripts/check.sh  # 仓库噪声扫描 + 提交信息格式
```

CI 执行同一组命令，没有第二套。

## 四、数据库

数据库为 PostgreSQL，驱动 `pg`。开发库与测试库必须是两个不同的数据库，配置写在各自的 `.env.local`（从 `.env.example` 复制）。

```sh
cp .env.example .env.local   # 首次；文件已存在时不要覆盖
```

本机没有 PostgreSQL 时，用容器起一个（数据目录挂到仓库外或已忽略的 `pgdata/`）：

```sh
docker run -d --name shihuguan-pg \
  -e POSTGRES_USER=app -e POSTGRES_PASSWORD=app \
  -e POSTGRES_DB=shihuguan_dev \
  -p 5432:5432 -v "$PWD/pgdata:/var/lib/postgresql/data" postgres:17-alpine
```

配置在首次读取时校验（`src/server/config/env.ts`），只报字段名不回显取值。

## 五、Next.js 16 的三个行为变更

- `middleware.ts` 已更名为 `proxy.ts`，且只支持 Node 运行时。**按旧名字写鉴权拦截不会报错，也不会生效。**
- `cookies()`、`headers()`、`params`、`searchParams` 全部是 Promise，必须 `await`。
- 自定义 webpack 配置会让 `next build` 直接失败（Turbopack 为默认构建器），有需要时用 `--webpack` 或改写配置。

## 六、目录约定

按开发书与团队执行方案第 5 节：

```
src/app/            页面与路由处理器（薄）
src/contracts/      共享 schema、类型、错误码（C）
src/features/       cabinet / viewer / studio / story（A、B）
src/server/core/    业务规则（C）
src/server/db/      数据访问与迁移（C）
src/server/auth/    身份与会话（C）
src/server/integrations/ai/  AI 适配（D）
src/server/assets/  素材字节处理（D）
tests/              单元与集成测试
```

客户端模块（`src/features/**`、`src/app/**` 的非 `api` 部分）被 lint 禁止导入 `@/server/db`、`@/server/auth`、`@/server/config`、`pg` 与 `node:fs`。碰到服务端数据要走路由处理器或 server action。

## 七、三维依赖的两个待决点（A 的 PR 里落实）

- **three 用 0.185.1，不用 0.186.x。** three r186 移除了 `PCFSoftShadowMap` 常量，`<Canvas shadows="soft">` 正好映射到它，运行时只打警告并回退到 `PCFShadowMap`；同时 `Source` 已改名为 `TextureSource`。@types/three 0.186.0 与 0.186.1 也不完全对齐。等场景稳定后再整体评估升级。
- **`frameloop="demand"` 在建场景时就定下来**（开发书 §7 静止时按需渲染）。后改会影响所有场景。

three 不自带类型，必须同时装 `@types/three`，且次版本与 three 对齐。
