## 二、首次安装

```sh
# 1. 装依赖（严格按锁文件）
pnpm install --frozen-lockfile

# 2. 装提交钩子（每个 checkout 一次）
bash scripts/install-hooks.sh
```

pnpm 10 默认不执行依赖的构建脚本，需要构建的依赖列在 `pnpm-workspace.yaml` 的 `onlyBuiltDependencies` 里。新增原生依赖时补进去，否则运行期才报错。

## 三、检查与启动

```sh
pnpm run dev         # 开发服务器，默认 http://localhost:3000
pnpm run typecheck   # tsc --noEmit
pnpm run lint        # eslint .
pnpm run test        # 不需要数据库的单元测试
pnpm run test:db     # 必须连接真实隔离测试库，缺配置或连接失败即失败
pnpm db:migrate      # 对 DATABASE_URL 执行迁移
pnpm run build       # 生产构建
pnpm run check       # typecheck + lint + test
bash scripts/check.sh  # 仓库噪声扫描 + 提交信息格式
```

CI 执行同一组检查，并启动 PostgreSQL 17 服务运行 `test:db`。`check` 不包含数据库检查和生产构建，完整验证需另外执行 `test:db` 与 `build`。

已有证据：`main` 提交 `4902f98` 的 [CI 39973854790](https://github.com/kumu314/Museum-of-Old-Objects-and-Memories/actions/runs/39973854790) 已通过冻结安装、类型、lint、3 个配置测试及生产构建；该旧运行不包含数据库或三维运行验证。新增检查的远端结果以修复提交后的 Actions 为准。

## 四、数据库

数据库为 PostgreSQL 17，驱动 `pg`。`compose.yaml` 提供独立的开发和测试实例，仅监听回环地址，默认端口为 55432 / 55433。开发数据保存在 Compose 项目独立卷中，测试数据使用临时内存目录；测试账号无法通过该账号连接另一个实例。样例账号仅用于本机开发，不能用于对外部署。

```sh
# 每个 checkout 使用独立项目名；同机多人也应改变宿主端口。
docker compose -p shiwuguan-local --profile test up -d --wait
# 首次复制；文件已存在时不要覆盖
cp .env.example .env.local
pnpm db:migrate
pnpm run test:db
# 停止本 checkout 的服务，保留开发数据卷；不要加 -v
docker compose -p shiwuguan-local --profile test down
```

可以通过 `SHIWUGUAN_DEV_PORT` / `SHIWUGUAN_TEST_PORT` 更换 Compose 端口，同时修改自己 `.env.local` 中的连接 URL。数据库配置由命令自动读取 `.env.local`，CI 则使用进程环境。测试必须提供 `DATABASE_URL` 与 `TEST_DATABASE_URL`，只连接后者；缺失时明确失败，不静默跳过。URL 必须明确主机、端口（可缺省为 5432）和库名，不允许查询参数覆盖目标；不同账号、协议别名和常见回环地址仍指向同一库时拒绝。不同 DNS 别名可能指向同一服务器，数据库与账号权限仍必须真正隔离。

迁移规则见 [SQL 迁移说明](../migrations/README.md)。执行器具备连续编号、校验和、并发互斥、事务回滚和重复执行检查。集成测试在真实测试库中创建本次随机命名的 schema，验证连接、DDL 迁移、重复运行、历史修改拒绝、提交后跨连接读取和约束失败回滚，结束后只清理该 schema。

当前没有展馆业务表。测试 SQL 是明确标识的基础设施夹具，不代表保存、确认、发布或快照规则已经实现；这些业务路径需随对应模块加入真实数据库回归测试。配置仍在首次读取时校验，启动强制校验入口尚未建立。

## 五、Next.js 16 的三个行为变更

- `middleware.ts` 已更名为 `proxy.ts`，且只支持 Node 运行时。**按旧名字写鉴权拦截不会报错，也不会生效。**
- `cookies()`、`headers()`、`params`、`searchParams` 全部是 Promise，必须 `await`。
- 自定义 webpack 配置会让 `next build` 直接失败（Turbopack 为默认构建器），有需要时用 `--webpack` 或改写配置。

## 六、目录约定

按开发书与团队执行方案第 5 节：

```
src/app/            页面与路由处理器（薄）
src/contracts/      共享 schema、类型、错误码（C）
src/features/       cabinet / viewer / studio / story（A、B）
src/server/core/    业务规则（C）
src/server/db/      数据访问与迁移（C）
src/server/auth/    身份与会话（C）
src/server/integrations/ai/  AI 适配（D）
src/server/assets/  素材字节处理（D）
tests/              单元与集成测试
```

客户端模块（`src/features/**`、`src/app/**` 的非 `api` 部分）被 lint 禁止导入 `@/server/db`、`@/server/auth`、`@/server/config`、`pg` 与 `node:fs`。碰到服务端数据要走路由处理器或 server action。

## 七、三维开发基线

- **three 用 0.185.1，不用 0.186.x。** three r186 移除了 `PCFSoftShadowMap` 常量，`<Canvas shadows="soft">` 正好映射到它，运行时只打警告并回退到 `PCFShadowMap`；同时 `Source` 已改名为 `TextureSource`。@types/three 0.186.0 与 0.186.1 也不完全对齐。等场景稳定后再整体评估升级。
- **`frameloop="demand"` 在建场景时就定下来**（开发书 §7 静止时按需渲染）。后改会影响所有场景。

three 不自带类型，必须同时装 `@types/three`，且次版本与 three 对齐。
