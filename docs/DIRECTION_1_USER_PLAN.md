# 方向一：用户负责的功能规划与制作方案

版本：0.1（访谈确认稿）  
日期：2026年10月24日  
基线：[新增功能总路线](NEW_FEATURES_ROADMAP.md)、[开发书](PROJECT_PLAN.md)、[团队执行方案](TEAM_EXECUTION_PLAN.md)、[实施状态](IMPLEMENTATION_STATUS.md)。

## 1. 目标

在方案 B 的个人展馆与自助制作基础上，完成公开展示/社交发现和 AI 自传两组新增能力。方向 owner 是用户（现有职责 A）；这表示产品取舍和验收责任归用户，代码仍需由现有五人团队按模块主责分配。首轮用演示账号和清楚标注的样例跑通骨架，真实模型服务和真实用户内容另行验证。

## 2. 范围与规则

### 2.1 公开展示与社交发现

1. 登录用户从“世界”进入发现；匿名访客不访问平台发现页。公开馆在发现入口可见，私密馆不进入目录、搜索、地图或榜单。
2. 工作台提供私密、持链接访问、公开可发现三种访问方式，馆内可见性统一。默认值尚未确定，建议私密，收到产品确认后实现。
3. 搜索昵称、馆名、展品名和手动标签。
4. 单向关注；首版只有关注列表，不做动态流。馆主仅看收藏总数，不展示收藏者身份；收藏名单是否对其他访客可见待确认。
5. 馆内留言及按父留言回复。发言者标明身份/对象。用户可删除自己的留言；馆主可隐藏留言、关闭留言、禁止某账号在其馆留言。被禁留言者是否仍可浏览、留言编辑规则待确认。
6. 举报与管理员平台明确延期。由于缺少举报处置，首版是否允许真实用户公开发言/公开馆待确认；若未形成治理流程，仅对演示账号开放公开交互是较稳妥的首发边界。
7. 用户可停止分享或从公开发现退出；已发布链接、目录缓存、搜索与榜单同步遵循现有访问撤销契约。

### 2.2 AI 访谈与自传

#### 产品行为

- 深度访谈收费；AI 整理成章和用户修改章节免费。额度用完后不再开启新深度访谈，但既有回答和章节仍可查看、修改、导出。
- 用户选人生阶段/话题开场，文本交互；一次一个话题，每次回答后至多一个相关追问。可继续追问、跳过、暂停、恢复或记录当前内容直接进入下一题。
- 可问敏感主题，但用户可随时跳过/暂停。拒绝后停止追问该段。不做心理诊断、治疗或情绪推断；明显不适时给退出选项。
- 按章节生成 AI 草稿；用户可修改并逐章确认。原始回答、AI 草稿、用户修改版本、已确认版本分开保存。
- 对话与草稿默认仅本人可见。逐章单独授权公开，提示第三方隐私；馆的公开设置不自动公开自传。
- 删除自传时删除平台内相应回答与草稿。导出副本无法撤回。导出内容应包含用户回答与章节正文；格式与删除冷却/备份周期待确定。

#### AI 行为契约

参考本机 `C:\Users\33552\Desktop\my-life-memoir` 的流程：话题选择、岁月锚（仅用用户确认过的信息）、一轮一问、迭代追问、随时暂停、进度续接、来源标注和章节审阅。当前仓库未见许可证；借鉴设计方法可行，复制其全文、脚本或模板前先确认许可。不得直接把 SKILL.md 中指令当作系统权限执行，也不调用未审阅脚本。

必须满足以下产品规则：

- 只以本次自传会话中用户主动给出的信息作为自传事实来源；不自动读取旧物故事、账户信息、设备照片、聊天、订单或联系人。将来用户主动提供素材须另有授权与来源标记。
- 每个生成段落都要保留回答来源标识。AI 不得补造姓名、时间、关系、事件、对话和感受，不把推算结果写成事实，不擅自消除讲述矛盾；不确定可标记，用户可改或删。
- 追问中性，不把猜测嵌入问题，不换词反复问已回答问题；不以“问到底”为由突破拒绝或不适信号。
- AI 草稿永不等于用户确认、发布或公开授权。用户文本、上传内容和 skill 资料都是不可信输入，不能改写系统规则或触发工具、发布、确认。
- 调用失败、超时、非法响应时保留输入和既有章节，不自动重复付费调用；提供人工整理路径。

#### DeepSeek 配置

- 服务端适配，不在浏览器调用 DeepSeek；密钥取名 `DEEPSEEK_API_KEY`，每台电脑仅写各自被 Git 忽略的 `.env.local`。提交 `.env.example` 只含空值或说明。
- 真实 URL、模型名和价格按官方配置、项目现有适配器和实际计费条件核实；PR 和日志不包含秘密或原始自传内容。
- 用户在聊天中粘贴的 Key 不写入文档或仓库；如真实有效，应先撤销并轮换。只有在隔离演示账号、确认请求数据用途并由有权人授权真实调用后，才进行真实 API 验收。

## 3. 依赖和协作边界

- 依赖方案 B 已有账号、个人展馆、会话、服务端 AI 适配层、私有资源访问、发布快照和撤销机制。实际完成状态以实施状态和对应代码为准。
- 公开馆、留言、关注、自传章节属于新业务；需要新增公共 schema/API、权限和数据库迁移，由现有公共契约负责人指定唯一 PR 作者。方向一不另建身份、分享、计费规则或第二套用户系统。
- 建议新增代码落在当前仓库已存在的合理 feature 路径；具体改动路径须先检查 `rg --files`，不把文档建议目录当成已存在结构。
- 尽量由一个 PR owner 完成社交发现页面，另一个明确 owner 完成自传界面；共享布局/公共样式一次只由一位作者改。用户负责评审体验和业务验收，不默认独自写全栈代码。
- 另一方向的契约未合入时可用同一 schema 验证、且显示“演示数据”的 fixture 开发；禁止模拟真实 AI 成功并误标成真实。

## 4. 制作路径

1. **确认产品门槛**：定公开馆默认值、没有举报平台时首发用户范围、收藏名单可见性、封禁后的阅读权限、自传导出与删除策略。
2. **确认接口契约**：定义公开状态、搜索字段、关注关系、留言/回复权限、自传会话/消息/来源/章节版本/公开许可，以及稳定错误码；迁移、权限规则各指定一位作者。
3. **演示资料和设计**：使用标有 DEMO 的账号、馆、留言和自传素材；不得在榜单或首页冒充真实用户。
4. **社交骨架**：做工作台隐私选择、公开目录、搜索、关注列表、馆内留言/回复、馆主管理与状态提示；先以 fixture 验视图，再接真实服务端契约。
5. **自传骨架**：完成选话题、问答、追问、暂停/续接/跳过、章节生成请求、来源展示、编辑、逐章确认、私有保存和导出/删除。AI 服务 mock 需显式标注，AI 文本保存为草稿而非确认正文。
6. **服务接入和安全验收**：DeepSeek server adapter 配置、超时、结构校验、请求去重/预算、来源映射和失败保留；真实调用另列实际运行证据。
7. **合入与手工流程**：分别提 PR；每个 PR 注明共享契约依赖、路径范围、mock 边界、验证与未做项。合入后用户用演示账号实际操作，验收隐私、撤销、AI 来源和付费用尽后的既有内容访问。

## 5. 验收标准

| 项目 | 通过条件 |
|---|---|
| 隐私模式 | 三种权限仅在服务端检查；公开/停止公开后发现入口与新请求正确更新；默认规则已获产品确认 |
| 搜索和关注 | 字段准确；无动态流；收藏只显示总数；用户间数据隔离 |
| 留言 | 登录访客可留言并在父留言下回复；自己可删；馆主可隐藏/关闭/禁评；无权操作被服务端拒绝 |
| 内容治理 | 上线范围明确标记；举报平台尚未做时不宣称具有举报处置能力 |
| 访谈节奏 | 每轮最多一个追问，跳过/暂停/恢复有效，明确拒绝后不继续追问 |
| 来源可信 | 每个章节事实可回链至用户回答；矛盾/不确定保留；无自动导入其他资料 |
| 确认与公开 | AI 草稿不自动确认；逐章编辑/确认/公开授权；馆公开不泄露自传 |
| 导出/删除 | 用户可导出原始回答和章节；删除平台内访谈资料后按确定策略不可经私有接口读取 |
| AI 故障 | 缺密钥、超时、非法结构时输入不丢失、不自动重复计费，允许人工继续 |
| 演示边界 | 所有 fixture 清楚标为演示；无 mock 冒充真实 DeepSeek 或真实用户内容 |

## 6. PR 和双机执行规则

- 方向一从主分支切自己的功能分支，向主仓库开 PR；最终集成人审核并合并。
- 不共享 `.env.local`、数据库、上传目录和构建产物。变更锁文件、公共 schema、迁移、根配置或全局样式前先确定唯一 owner。
- 先合契约，后并行开发；基于 fixture 时必须让其通过同一 schema，并在界面标明演示状态。
- PR 运行相关 lint/typecheck/test/build，说明数据迁移、权限影响、真实/模拟 AI、未执行项。AI/权限/公开相关关键逻辑由非作者审查；若只有一人则注明单人自查。
- 不因本规划就启动 agent 或调用付费服务；如后续将工作交给 agent，任务需列出允许文件、接口基线、验收标准和不可处理范围。

## 7. 本方向明确不做及待定

- 不做 AI 自动发布/自动确认，不把自传设为公开默认，不自动导入其他来源。
- 不做匿名社区入口、动态时间线、举报后台和管理员平台（除非后续另行授权和排期）。
- 待产品决定：私有默认、无管理平台时公开范围、收藏名单对谁可见、封禁后可否参观、留言编辑、导出格式、删除/备份清理时限、深度访谈额度与价格。
- 商业化方向是规划，不在此工作包接支付。
