# 拾物馆：五人团队分工与交付方案

版本：1.3\
更新日期：2026年10月24日\
制作模式：方案 B，用户自助建馆并从上传照片生成 3D 模型\
适用基准：[PROJECT_PLAN.md v0.7](PROJECT_PLAN.md)、[AGENTS.md v1.1.0](../AGENTS.md)；环境与 Git 操作见 [提交手册 v1.3](提交手册.md)

本方案安排从现有工程到最终成品的完整责任，不安排未经确认的日期或工时。各成员持续承担所属模块的实现、联调、修复和交付，完成某个验收包不代表责任结束。技术经历来自成员自述，不作为能力认证；具体姓名、可投入程度及关键变更复核人由团队登记。

现有代码源自方案 A 的团队制作工程。个人归属隔离、照片生成模型及完整自助流程仍需实现或验收，当前状态见 [实施状态](IMPLEMENTATION_STATUS.md)，逐项结果见 [验收清单](11-验收清单.md)。本文件中的新目录、接口和任务不表示已经存在。

## 1. 组织方式

### 1.1 五位成员与最终主责

| 代号 | 对应成员 | 最终主责 | 最终交付物 |
| --- | --- | --- | --- |
| A | Codex（用户本人） | 产品取舍、动态模型接入、3D 展柜与检视 | 用户生成的模型能正确陈列、取出、旋转、缩放和返回 |
| B | 另一位组员 | 用户账号界面、自助工作台、故事与参观界面 | 普通用户能独立上传、生成、预览确认、发布及再次编辑 |
| C | Spring Boot / MyBatis / Vue 组员 | 用户数据、生成任务、权限、工程集成与部署恢复 | 用户隔离、任务可恢复、素材与快照正确、可实际交付的运行版本 |
| D | Python / Django 组员 | 真实三维生成、结果处理、故事 AI、图片音频处理 | 可接入的生成模型，以及真实效果、耗时、成本和失败处理证据 |
| E | 提交《个人技术情况说明》的组员 | 测试素材、自助试用、生成质量、设备验收与交付材料 | 可复现验收记录、完整样例、操作说明和简短演示视频 |

A 决定产品范围和体验取舍，C 决定现有技术栈内的工程组织与集成方式。涉及服务、费用、账号接入或产品范围的选择，由相应负责人给出实测和代价，A 确定后记录。各模块作者负责自己的局部测试和联调问题，C 不承担重写全部模块的责任。

### 1.2 分工依据

A 与 B 按三维与业务界面拆分；C 负责数据、任务与事务；D 负责外部调用和模型、图片、音频的实际处理；E 负责独立输入、试用和质量证据。C、D 沿用现有 TypeScript 工程，Python 可用于离线处理与验证，不按个人熟悉的框架增加 Spring Boot、Django 等重复业务服务。E 不承担独立复杂建模或核心安全代码的最终复核。

## 2. 产品边界与共同目标

产品范围、用户确认、发布规则、样例和输入要求以 [开发书第 3—6 节](PROJECT_PLAN.md#3-制作方式与决策) 为准。本方案只维护人员任务、模块归属和交接，不另设第二份产品边界。每位作者对最终自助流程中的所属模块负责，阶段提交或 PR 合入不结束责任。

## 3. 每个人负责到什么结果

### 3.1 A：产品与动态三维体验

- 复用现有六格展柜和四态检视，接入用户生成的模型资产及版本。
- 与 D 确定模型格式、尺寸、朝向、原点、纹理及资源预算；保持规则统一，不逐件写临时展示补丁。
- 验证不同模型的入柜、选中、取出、旋转、缩放、返回、快速切换和窗口变化。
- 与 B 对齐唯一选中状态、故事面板、音频停止和手机交互；保留实拍、故事、模型失败及 WebGL 故障入口。
- 验收最终视觉、可用性和范围取舍，修复三维模块的联调缺陷。

**结束条件：**用户生成的新模型在演示电脑和实际手机上按已确定的支持范围运行，能够正确陈列与检视；失败保留故事入口。内置模型运行通过不能代替动态模型验收。

### 3.2 B：用户自助制作与参观界面

- 将现有团队界面发展为用户登录与账号接入、我的展馆、首次引导及个人工作台。
- 完成照片与讲述上传、生成提交、真实任务状态、刷新恢复、失败重试和候选模型预览采纳。
- 完成故事草稿对照、编辑、当前版本确认、发布、链接交付、换链、停止分享及再次编辑。
- 保护未保存输入；处理身份失效、版本冲突、任务过期、用量限制和网络失败，不自动覆盖或重新付费提交。
- 完成桌面和手机界面、键盘与中文输入法检查；与 A 联动故事、实拍、音频和返回行为。
- 修复浏览器自助流程暴露的所属界面问题，补齐相关使用说明。

**结束条件：**普通用户无需队员代操作，完成账号接入、上传、真实生成、预览采纳、确认、发布及再次编辑；刷新、重新登录或失败后能继续制作，另一浏览器和实际手机可参观。

**边界：**B 呈现服务端状态，不复制发布、归属和计费规则；三维状态由 A 的控制器提供，不建立第二份选中状态。参观页的共享文件先确定一位作者，A、B 不并行修改同一文件。

### 3.3 C：用户数据、生成任务与工程交付

- 维护公共 schema、错误码、用户身份和会话，落实展馆、展品、素材、任务、结果采纳、确认和发布的完整归属校验。
- 以新增连续迁移处理已有团队账号与数据的归属；保留旧快照与素材，不清库或重写已应用迁移。
- 持久化生成任务、输入及版本、外部任务标识、状态与结果；实现提交去重、状态查询、重启核对和明确的新一轮生成。
- 与 D 确定外部提交结果不明、超时和重试的处理；落实每用户用量与并发限制，不盲目重复付费提交。
- 将生成模型纳入私有资产、版本、不可变快照和授权读取；替换模型使旧确认失效，不破坏旧快照。
- 负责文件与数据库分步提交、上传中断和响应失败检查；统筹模块集成与共享配置。
- 完成生产构建和目标环境部署、任务运行与重启恢复、数据库和素材配套备份恢复；交付真实操作说明。

**结束条件：**两个用户之间的私有资源与任务隔离，刷新及重启不丢任务或误重提；模型与作品可发布、撤销并恢复。E 能按说明复现运行和恢复后的参观，各模块检查以最终实际提交为准。

**边界：**C 负责业务编排和保存，D 负责服务协议和字节处理；各作者修复各自模块问题。关键权限、迁移和发布行为由 D 交叉复核。

### 3.4 D：真实三维生成与素材处理

- 优先验证可用三维服务的真实 API、输入张数与拍摄要求、支持物品、输出格式、耗时、费用、额度和素材使用条件，形成 A、C 可评估的记录。
- 实现提交、查询和获取结果的适配器，明确超时、服务失败及不确定提交结果；如使用回调，与 C 落实来源验证和重复回调处理。
- 将生成结果按不可信外部资产解析、校验与规范化，输出可保存的自包含 GLB、预览及模型元数据；不依赖供应商临时地址永久展示，不允许任意外部资源引用。
- 与 A 实测并冻结文件、几何体和纹理预算、朝向及落点规范；给 C 提供明确处理结果和失败类型。
- 继续完成真实故事 AI、输出与来源校验、过期采纳保护，以及图片方向、敏感元数据、音频格式和解析限制。
- 与 C 验证模型文件完成、事务回滚、进程中断及响应失败的处理；交叉复核 C 的权限、发布和迁移。

**结束条件：**新上传的合理照片真实生成可加载模型，结果可规范化保存并进入展柜；失败保留输入和已有内容。真实服务效果、耗时、成本与支持边界可复查，文字 AI 和允许媒体格式通过相关验收。

**边界：**D 不另建用户、数据库、发布或任务业务系统；外部任务 ID 和本地任务归属由 C 管理，适配器不直接确认或发布。

### 3.5 E：自助流程、生成质量与最终材料

- 准备三件完整样例、新的合理照片及缺失、模糊、矛盾、不确定等测试输入，记录素材许可及第三方生成用途。
- 整理拍摄指引与素材缺口，记录模型输入、真实输出、近似程度、耗时和成本，不逐件替普通用户制作或确认。
- 组织陌生用户独立完成账号接入、上传、生成、预览、确认与分享，记录卡点、成功情况和反馈，不由队员代操作后宣称自助成功。
- 按验收清单组织两个用户的数据隔离、任务去重恢复、旧结果、旧快照和分享撤销检查，以及电脑、实际手机和跨浏览器操作。
- 维护可复现缺陷、责任人、修复及复测证据；各模块作者负责修复，E 持续跟进到关闭或明确交付阻塞。
- 按 C 的说明复现生产运行与隔离恢复；整理样例来源、操作说明、实际验收、未完成项、成本记录和简短演示视频。

**结束条件：**新的合理输入能完成真实生成与发布；普通用户可独立制作，完整样例、许可、电脑和手机证据齐备。交付材料如实区分已通过、失败、未执行和受阻，不能以固定演示或录屏替代产品验收。

## 4. 技术方案：保持一套运行体系

复用现有 Next.js、TypeScript、React、Three.js、Zod、PostgreSQL 与私有素材目录，实际版本以锁文件和运行说明为准。本次不升级依赖、不更换框架。文字 AI 与三维生成分别适配，业务身份、任务、资产和快照仍在统一工程。

C、D 按实际服务选择最小充分的异步执行方式。任务必须持久化并能重启核对，但不提前增加大型队列平台或多套业务后端；如需任务进程、原生依赖或模型处理程序，先明确必要性、生命周期、部署入口和恢复方式并记录。付费调用及部署按当前授权执行，本分工不自动授权费用或外部传输真实素材。

## 5. 目录与公共文件归属

| 范围 | 主责 | 边界 |
| --- | --- | --- |
| `src/features/cabinet/**`、检视控制器、模型展示适配 | A | 动态模型展示和三维状态；不直接访问数据库或生成服务 |
| `src/features/studio/**`、登录与个人页面、参观页故事和媒体界面 | B | 用户自助操作；与 A 的共享展示文件由一位明确作者修改 |
| `src/contracts/**`、`src/server/core/**`、`src/server/db/**`、`src/server/auth/**`、迁移和 API 路由 | C | 用户归属、任务与资产业务编排、事务和发布；新模块按实际工程建立 |
| `src/server/integrations/ai/**`、三维生成适配器、`src/server/assets/**` | D | 外部协议、结果获取、模型及媒体处理；生成适配器为待实现模块 |
| `scripts/content/**`、`tests/e2e/**`、`tests/fixtures/**`、内容和验收材料 | E | 测试与证据；真实素材和凭据不入 Git，各作者仍负责局部测试 |
| 依赖、锁文件、构建、CI、根布局和公共配置 | C 统筹 | 由明确的一位作者修改，使用者核对影响 |
| 全局样式和界面约定 | B | 涉及场景容器与 A 共同核对 |
| 模型展示规范、内置资产清单 | A | D 负责生成资产规范化，E 提供输入和来源证据 |

新增任务和模型资产 schema、迁移及目录以真实实现确定，不能在消费者各建一套兼容类型。真实配置、客户照片录音、模型结果和数据库不提交 Git；测试资产仅使用获准公开或脱敏内容。

## 6. 必须对齐的交接

| 交接 | 交付方 → 使用方 | 约定内容 |
| --- | --- | --- |
| 用户与归属 | C → B、D | 用户身份、资源归属、会话失效、不可见资源响应；不暴露他人私有资源 |
| 生成任务 | C、D → B；E 验证 | 输入资产及来源版本、本地任务 ID、状态与结果、失败和显式重试；前端不接触外部密钥 |
| 模型资产 | D → C → A、B | 自包含 GLB、资源预算、原点朝向、资产版本、预览、近似程度；C 保存并提供授权读取 |
| 展示数据 | C → A、B | 当前快照、展品与格位、模型资产引用、展签及媒体；不夹带原始讲述、输入照片清单或内部路径 |
| 检视状态 | A → B | 当前展品与四态的唯一来源、选择及返回入口、音频切换条件 |
| 故事 AI 与媒体 | C、D → B；E 核对 | 来源版本、草稿、追问、有效媒体、失败类型和过期结果处理 |
| 试用与修复 | E → 各作者 → E | 输入、步骤、环境、预期和实际结果、责任人、修复提交及复测证据 |

公共类型从 schema 推导。接口未完成可使用同一 schema 校验且明确标识的 fixture 开发；fixture 不得冒充真实生成、保存或发布成功。

## 7. 交付依赖与推进方式

以第 3 节每个人负责到成品的任务为准。依赖只用于安排交接与合入次序。

| 需要对齐的内容 | 交付与使用关系 |
| --- | --- |
| 用户归属、任务和模型资产契约 | C 统筹，A、B、D 核对各自输入输出 |
| 真实建模及输出规范 | D 真实验证，A 检查展示，C 核对任务和存储，E 提供独立输入 |
| 上传、任务状态与模型预览 | B 接入 C、D 的真实流程和 A 的展示能力 |
| 确认、快照与分享撤销 | C 提供权威规则，B 完成操作，D 交叉复核，E 复现 |
| 最终交付 | C 负责部署与恢复，E 组织完整验收和材料，A 验收体验，各作者修复所属问题 |

D 的建模验证、C 的用户归属、A 的动态展示、B 的自助界面和 E 的素材准备可并行。契约与依赖先合入，随后接真实服务、数据和资产。服务未确定时，独立且已授权的工作继续推进，不伪造生成成功。

## 8. 验收与复核

### 8.1 责任分配

| 对象 | 实现主责 | 复核或验收 | 关键证据 |
| --- | --- | --- | --- |
| 用户、归属和迁移 | C | D 复核，E 独立复现 | 两个用户的列表、读写、素材、任务、采纳、确认与发布隔离 |
| 生成任务、重复提交与恢复 | C、D | 非作者复核；E 复现 | 真实任务、刷新、重启、提交不明、失败和用量限制 |
| 模型与媒体处理 | D；C 编排，A 展示 | C、A 核对，E 抽检 | 新照片真实结果、格式资源校验、私有资产与快照、设备效果 |
| 确认、发布和分享 | C；B 界面 | D 复核，A 验收，E 记录 | 确认失效、冲突、旧快照、模型素材授权与撤销 |
| 故事 AI 与自助界面 | D、C、B | C 复核技术边界，E 试用与事实核对 | 真实调用、失败保留、过期结果、无人代操作的制作流程 |
| 3D、故事和媒体 | A、B | E 实际操作，A/B 核对边界 | 新生成模型、快速切换、返回、WebGL 和实际手机 |
| 部署与恢复 | C | E 按说明复现，各作者配合 | 生产构建、私有素材、任务重启核对、配套恢复后的实际参观 |

关键变更复核沿用开发书 §7.1。参与实现者的检查不能记为独立复核；仅一人可参与时，单独复查差异与证据并记录为单人自查，编码助手不计作另一位人工复核者。

### 8.2 完整产品的共同结束条件

完整要求和实际结果统一见 [验收清单](11-验收清单.md)，最终材料见开发书 §10.3。本方案不再复制场景表；E 组织验收，各作者持续修复直至共同结束条件满足。

### 8.3 统一交付口径

交付说明包含实际完成、改动范围、复现方式、验证层级、结果、未执行项和限制。每项新增验收先登记为未实现或未执行，实际运行后再更新，保留原方案 A 的历史证据及适用范围。模块作者持续修复所属问题直至整体验收，不将“代码已生成”或“页面可打开”视为完成。

## 9. AI 协作与变更管理

授权、安全、独立工作目录、公共文件协调和 Git 操作沿用 AGENTS.md 与提交手册。每项任务回报所属模块、实际变更、复现与验证、未执行或受阻事项、联调修复及复测证据，不新增另一套任务模板或协作平台。

## 10. 文档分工

开发书维护目标与验收要求；本方案维护长期主责和依赖；AGENTS.md 维护工程规则；提交手册维护 Git 与隔离环境；运行说明只记录真实命令和运行边界；实施状态概括当前进度；验收清单是唯一逐项结果记录；内容包模板维护测试素材、来源与确认记录。产品、契约和操作变化时同步相关文档，不把目标描述当作已实现证据。
