项目代号：拾物馆，暂定\

本文描述目标与实施约定，不代表产品已经实现。最终成品采用方案 B：用户自助建馆，并新增照片生成 3D 模型能力，决策记录见第 3.4 节。现有团队制作代码属于可复用基础，不代表新目标已经完成。人员职责、交付依赖与复核安排见 [团队执行方案](TEAM_EXECUTION_PLAN.md)；环境与 Git 协作见 [提交手册](提交手册.md)。

## 1. 我们要做什么

我们希望把旧物和它背后的故事，做成一座可以打开、观看和分享的数字收藏柜。

用户看到的不是一张文件列表，而是一座有格位、有灯光、有物品纵深的 3D 展柜。点击一件旧物，可以把它取出、旋转查看，同时阅读物主的讲述、查看实拍照片、播放原声。

产品的价值来自三件事：

- 把散落的照片、录音和记忆整理成完整内容。
- 用展柜和检视动作，让旧物值得被停下来观看。
- 把结果交付给另一个人，使其能通过链接参观。

首版先围绕“为家人制作一份旧物纪念展”展开。这个场景仍是需要验证的产品假设，不能直接当作已经成立的市场需求。

## 2. 谁会使用它

项目中需要区分四种角色。实际使用时，一个人可能同时承担多种角色。

| 角色 | 关心的问题 |
| --- | --- |
| 客户 | 能否得到一份适合送给家人或自己保存的纪念作品 |
| 物主 | 故事是否准确，哪些内容可以展示 |
| 制作者 | 能否顺利收录素材、整理内容、制作并交付 |
| 参观者 | 能否方便打开、看懂故事、查看物品和播放原声 |

首版需要验证的主要问题是：

1. 对方是否愿意提供旧物照片和讲述。
2. 整理后的故事是否让物主感到准确。
3. 展柜是否让参观者愿意继续打开下一件旧物。
4. 最终结果是否值得保存、分享或付费制作。

“觉得有意思”与“愿意付款”是不同的信号，记录反馈时需要分开。

## 3. 制作方式与决策

### 3.1 用户自助建馆与模型生成

采用方案 B：用户自行创建展馆，上传旧物照片与讲述，生成 3D 模型和展签草稿，预览、修订并确认后发布。

**用户登录 → 创建个人展馆 → 上传照片与讲述 → 生成模型与展签草稿 → 预览、采纳与确认 → 入柜 → 发布分享 → 后续编辑或撤销**

完成标准是普通用户无需队员陪同或代操作，独立完成制作与分享。

### 3.2 现有工程的使用方式

复用已有团队制作工程中的素材、事务快照、分享与展柜能力；用户身份和现有资源归属隔离已接入，继续补齐生成任务和动态模型资产。旧方案 A 不再保留为待选制作流程，不建设双模式框架。

### 3.3 范围归属

第 4 节定义必需与可选功能，三维生成约定见第 6.1、9.6 和 9.7 节。人员最终任务统一维护在团队执行方案，当前实现与验收分别维护在实施状态和验收清单。

### 3.4 决策记录与启动条件

历史基线 v0.6 于 2026年10月23日采用方案 A。2026年10月24日用户明确后续目标为“用户自己上传然后生成模型，也就是方案 B”，据此将最终成品改为用户自助建馆加自动建模。A（Codex，用户本人）负责产品取舍，C 负责工程组织，B—E 持续负责各自模块直至整体验收，不能以完成某个阶段结束责任。

| 决策记录项 | 当前状态 |

| 工程组织负责人 | C，具体姓名及可投入程度在开工时登记 |
| 选定模式 | 方案 B：用户自助建馆，上传照片生成 3D 模型 |

已明确的任务可在授权范围内推进。制作模式已记录不等于自动授权应用编码、Git 操作、调用付费服务或部署；进入对应工作时沿用当前用户授权。后续若调整模式，由 A 决定，C 说明数据、身份和接口影响，并同步相关文档。

### 3.5 成员 A 动态模型接入的实施范围（2026-10-24）

用户已明确后续采用自助建馆，并增加照片生成三维模型能力：**用户登录 → 建馆 → 上传旧物照片与故事 → 生成模型与文字草稿 → 预览调整并确认 → 发布分享**。原方案 B 仅描述自助制作，照片生成模型属于本次明确补充的目标；生成近似效果仍需如实标识，并保留实拍和故事。

成员 A 本次交付动态 GLB 接入、陈列方向与大小、可嵌入制作页的预览组件，以及检视、替换和失败行为验证。账号与个人归属、生成任务持久化、模型素材与发布快照契约由 C 继续组织，D 对接生成服务与文件处理，B 接入自助页面，E 提供获准样例并独立试用。具体接入说明见 [模型预览接口](../src/features/viewer/MODEL_INTEGRATION.md)。

当前测试 GLB 仅证明动态加载和三维交互；真实照片生成结果、服务质量与成本、跨用户隔离和完整发布链路须分别验收。本轮不选择付费服务或提交真实照片；模型读取限于本站受控地址，生成资产不得放入公开静态目录，也不能直接把服务商下载地址交给参观页。

## 4. 首版做什么

2026-10-24 补充确认：每账号一座有效展馆、每页六格可翻页；登录后有保存展品进入本人预览，无展品进入工作台；一件旧物对应自己的回忆和展签，全馆简介独立编辑并展示在馆名下。混元先准备单图与正背左右四视图输入及提交契约，真实生成暂不接入。产品、迁移与接口边界见 [个人展馆流程](PERSONAL_MUSEUM_FLOW.md)。

首版围绕一条完整流程组织功能：

**个人建馆 → 上传素材与讲述 → 生成模型与展签草稿 → 用户预览确认 → 发布 → 他人参观**

### 4.1 共同必须完成的能力

| 能力 | 首版内容 | 完成标准 |
| --- | --- | --- |
| 用户身份与个人空间 | 用户名+密码自助注册、登录、我的展馆、个人归属校验 | 用户只能制作和读取自己的私有内容，注册界面及完整流程仍需验收 |
| 旧物收录 | 名称、约略年代、照片、原始讲述，可附原声 | 保存后刷新仍可恢复 |
| 照片生成模型 | 真实生成服务、任务状态、预览与采纳 | 新的合理输入能生成可检视模型；刷新或重启可继续查询，不重复提交同一任务 |
| 故事整理 | AI 根据已有讲述生成展签草稿与必要追问 | 至少一次真实调用成功，失败不丢失输入 |
| 用户确认 | 审阅模型、展签及展示素材，明确确认当前版本 | 采纳新模型或修改公开内容会使旧确认失效，生成不自动发布 |
| 3D 展柜 | 有真实空间层次的柜体和格位 | 样例可以正常陈列与选中 |
| 重点检视 | 取出、旋转、缩放、放回 | 快速操作后物体与镜头仍能恢复 |
| 故事面板 | 展签、实拍照片、年代、原声 | 内容与当前选中展品一致 |
| 发布分享 | 发布当前确认内容，生成参观链接 | 另一浏览器登录后可凭有效链接读取当前快照 |
| 停止分享 | 停止访问或更换链接 | 旧链接的数据及私有素材新请求均失效 |
| 持久保存 | 保存展馆、素材与发布版本 | 重启服务后仍可读取 |
| 失败处理 | 文字 AI、三维生成、模型加载或网络失败时给出明确状态 | 用户输入与已有模型保留；图文入口不冒充模型生成成功 |

展签指随展品展示的短文。原始讲述、AI 草稿和已确认展签需要保持清楚的区别。上传格式、大小和尺寸统一使用第 9.7 节的取值，错误反馈统一使用第 9.8 节的契约。

### 4.2 方案 B 与自动建模的必需项

- 用户通过确定的账号接入方式登录，进入自己的展馆与工作台；服务端检查资源归属，不能继承团队成员共同访问所有展馆的权限。
- 用户自行上传照片和讲述、提交生成任务、查看状态与结果、预览并采纳模型、修订故事、确认当前版本和发布。刷新或重新登录后可以继续制作。
- 生成结果先保存为候选模型；采纳时核对输入和展品版本，产生新版本并使旧确认失效，不直接替换已发布快照。
- 用户在传输第三方生成服务前了解相应用途，并确认具有素材使用权；发布分享由用户另行明确操作。
- 三维生成必须真实可用，用新输入完成一次从上传到参观的全流程。失败保留原素材与已有结果，允许人工继续编辑；图文展示或内置模型不能算生成成功。

这些能力均按最终成品验收，不能只在前端模拟。

### 4.3 有余力再做

- 重点展品上的细节热点。
- 自动语音转文字。
- 浏览器直接录音。
- 二维码或图文导出。
- 额外视觉主题。

每次只增加一项，并确认共同必需能力已经通过验收。自动转写未进入首版前，不把它的实现和测试设为必需门禁。

### 4.4 首版不做

大型展厅漫游、多人实时参观、社区、交易、支付系统、多级组织权限，以及任意旧物的自动精确三维重建。

增加需求时，需要说明它替换哪项现有工作。

新增的公开展馆、社交发现、自传和共同记忆等想法统一记录在第 12 节，收费方向见第 11.1 节；目前作为后续产品方向，不自动纳入首版实现与验收。

## 5. 用户会看到什么

### 5.1 展柜

采用两行三列的展柜，每页六格，柜外提供翻页入口，不占用展位。全馆支持超过六件展品，发布包含所有页。演示准备三件完整样例，另以七件以上内容验证跨页流程。

视觉方向采用偏暗背景、暖色格内灯光和清楚的铭牌。柜内显示名称和简短年代，完整故事在选中后展开。

参考收藏柜的陈列与检视方式，柜体、材质和界面使用自己的设计。

### 5.2 检视

点击展品后，物品从格位中取出，进入适合观察的位置。用户可以旋转和缩放，通过返回按钮或 Esc 放回。

交互分为四个状态：

`overview → focusing → inspecting → returning → overview`

需要重点检查：

- 连续点击不会重复取出同一物品。
- 拖拽旋转只影响当前展品。
- 返回后柜体、物品和镜头位置正确。
- 切换展品时，上一段音频停止。
- 音频由用户主动播放。
- 手机有明确的选择和返回入口。

模型初始变换、包围盒适配与恢复目标遵循第 9.6 节。恢复不能依赖被打断时的动画位置。

### 5.3 样例与模型

保留六格展柜与三件完整样例，至少一件带获准原声。现有相机、磁带、车票模型可用于演示与回归，并明确其来源和近似程度。

- 用户生成模型是新增主流程。支持的旧物类别、拍摄要求和输入张数由 D 实测，A 确定后向用户说明，不承诺任意物品都能准确还原。
- 除固定样例外，使用新的合理照片完成真实生成、预览、采纳、确认、发布和参观，结果不能由预置资产替换。
- 所有展品保留实拍入口，生成模型标注其近似性；未拍摄的背面与内部结构不作为真实事实展示。
- 照片票据可保留薄片展示，生成失败可继续图文制作，但均不计作三维生成成功。

模型加载失败时显示实拍与重试入口；WebGL 不可用或运行期间上下文丢失时提供明确状态和图文参观入口。最终交付仍需完成生成模型的真实 3D 展示与检视。

## 6. AI 和故事如何配合

故事 AI 的职责是整理物主已经提供的内容，帮助表达和追问；三维生成另见第 6.1 节。

输入包括旧物名称、约略年代及带有来源标识的讲述片段。输出包括：

- 一段建议为 60 至 120 字的展签草稿。
- 最多两个追问，也可以没有。
- 关键内容对应的来源片段标识。

不得补造人物、年份、关系、事件和情绪。原文中的“约”“可能”“记不清”需要保留。

AI 输出先经过结构校验，再交给人审阅。来源标识有效只能证明结构正确，不能证明内容一定真实。

方案 B 中，用户在个人工作台核对当前版本的模型、展签、实拍及原声并执行确认。上传者与物主不同的，需取得相应授权；用户账号和自行点击确认不能代替其他权利人的许可。E 负责测试样例与独立验收，不逐件代替用户确认。

AI 超时或不可用时，保留已保存的素材与讲述，允许人工整理继续交付。测试样例与预先录制的结果必须明确标识。

### 6.1 照片生成模型

文字整理与三维生成使用不同的服务端适配器，输入、结果和失败状态分别呈现。三维生成过程为：校验照片与授权 → 持久化任务 → 提交真实服务 → 跟踪外部任务 → 获取并校验结果 → 保存候选模型 → 用户预览与采纳。

任务至少区分排队、执行中、成功和失败；成功指模型已经完整保存并通过入库校验，不能只凭外部服务返回成功就显示可用。刷新页面查询已有任务，服务重启后核对外部状态；提交结果不明时不得盲目重复付费提交。若服务不支持取消，不在界面承诺取消外部执行或退款。

用户重新上传照片、修改展品或删除草稿后，旧任务结果不得自动覆盖新内容。用户明确重新生成时建立可追溯的新任务，采纳另做来源版本检查。失败保留输入、已保存模型与已发布作品。

服务提供方、输入要求、输出格式、实际耗时与成本由 D 验证并记录；C 负责持久化、权限、用量限制和提交编排，A 负责模型展示规范，B 呈现真实状态，E 组织独立验证。

## 7. 五类职责怎样协作

人员分工、目录归属、接口交接和各自最终完成标准统一见 [团队执行方案](TEAM_EXECUTION_PLAN.md)。A 为 Codex（用户本人）；B—E 持续负责各自模块直到成品验收，姓名、投入程度和关键复核人由团队登记。

C 维护公共契约，所有消费者从 schema 推导类型，不各建一套字段。接口未完成时可以使用明确标识且通过 schema 的 fixture 开发，真实保存、建模和发布须接服务端。独立工作目录及 Git 协作按提交手册执行，AI 与子代理遵守当前授权。

### 7.1 关键变更的复核职责

复核限于本次变更涉及的规则、差异和验证证据，不另设所有任务都必须经过的完整评审流程。

| 变更类型 | 复核负责人 | 重点 |
| --- | --- | --- |
| 权限与素材访问 | D 复核 C 的权限与路由；C 复核 D 的文件模块 | 服务端身份、资源归属、分享素材访问和撤销 |
| 发布与分享流程 | D 复核规则，A 验收流程，E 记录证据 | 人工确认、版本检查、快照隔离及参观链路 |
| 数据库迁移 | D 复核 C 的变更 | 数据兼容、约束、迁移结果及备份恢复 |

实现前落实复核人的姓名。复核范围若由本人实现，或复核人无法解释相关规则与结果，由 C 协调另一位具备相关能力且非作者的队员；涉及 C 自身或无法协调时由 A 指定。不得把参与实现者的检查记作独立复核。

仅一人可参与本次工作时，由实现者在实现结束后单独复查差异与验证证据，记录为“单人自查”。AI 可以辅助检查，但不能记作另一位人工复核者。复核记录注明实现者、复核者或单人自查、验证证据及未解决项。

复核未完成、相关验证失败或未执行，或存在未解决的权限、数据一致性及恢复阻塞问题时，该变更不得作为可合入、可部署版本交付；允许注明未验收状态后交接当前成果与缺口。按上述方式完成单人自查与相关验证，不因缺少第二位成员自动阻塞交付。

交付依赖统一见 [团队执行方案第 7 节](TEAM_EXECUTION_PLAN.md#7-交付依赖与推进方式)。任务按最终结果负责，原方案 A 的通过记录只作原范围证据。

### 8.1 演示建议

1. 一位普通用户登录并创建自己的展馆。
2. 上传一组新的合理旧物照片和讲述，发起真实三维生成与文字整理。

| 部分 | 建议 |

首版部署保持单实例 Node 应用，连接独立的 PostgreSQL 服务，上传素材保存在服务端持久目录。PostgreSQL 的数据存储也必须持久化，不通过复制运行中的数据库目录共享开发环境。自托管入口配置参考[Next.js 官方说明](https://nextjs.org/docs/app/guides/self-hosting)。备份在暂停写入的同一窗口内生成 PostgreSQL 备份和素材目录副本，并验证配套恢复；数据库备份采用 `pg_dump` 自定义格式，恢复使用 `pg_restore`，参考 [PostgreSQL 备份与恢复文档](https://www.postgresql.org/docs/current/backup-dump.html)。当前工程已使用 PostgreSQL 18；实际迁移入口与部署验证边界见 [运行说明](运行说明.md)，不能将本地数据库验证视为生产恢复验收。

### 9.2 主要模块

- 页面与工作台负责输入和反馈。
- 故事模块负责展签、照片与音频展示。
- 场景模块负责柜体、模型、镜头与检视。
- 服务端负责身份、业务、数据库、素材和 AI。
- 公共契约负责请求、响应、展示数据和错误码。

### 9.3 最小数据实体

| 实体 | 作用 |
| --- | --- |
| 用户 | 登录身份、账号状态与可用权限；不能只靠 created_by 记录冒充归属校验 |
| 展馆 | 所有者、主题、版本、展品关系、当前发布状态 |
| 展品 | 名称、年代、格位、讲述、展签、展示方式和确认版本 |
| 素材 | 图片、音频、生成模型的用户及展馆归属、版本、格式、大小和私有存储位置 |
| 生成任务 | 用户、展品、输入素材及来源版本、外部任务标识、状态、结果与失败原因 |
| 整理草稿 | AI 输出、来源版本、追问和来源对应关系 |
| 发布快照 | 发布时冻结的公开内容与允许访问的素材集合 |

以上是目标实体，尚非全部现有 schema。现有账号与资源归属已通过迁移 0003 及服务端校验接入，迁移 0005 增加每账号一座有效展馆、跨页格位和建模照片准备。生成任务与模型资产仍由 C 使用新增连续迁移落实，不重写已应用迁移或清库。资源归属须覆盖列表、详情、写入、生成、采纳、确认、发布与素材读取。

发布快照指发布时冻结的一份内容。修改工作台草稿不会立即改变参观页面，再次发布后才更新。

必须保持的规则：

- 公开内容变化后，展品版本增加，旧确认失效。
- 保存与发布携带预期版本，冲突明确返回。
- 发布在事务中检查版本、确认状态、素材归属与格位；未确认内容阻止发布并列明需要处理的展品。
- 同馆有效展品不能占用同一格位。
- 替换图片、音频或生成模型产生新资产及版本，不覆盖旧快照引用的内容；生成成功先成为候选结果，用户采纳时检查来源版本并使旧确认失效。
- 草稿删除不破坏已有发布版本；首版不自动物理清理历史素材。
- AI 调用在数据库事务外执行，过期结果不能覆盖新编辑。
- 文件写入与数据库提交分别处理失败；只有完整可读的素材才被有效引用，不能因响应发送失败而误删已提交素材。

### 9.4 接口职责

| 接口组 | 职责 |
| --- | --- |
| 身份与会话 | 用户获得账号、登录、退出和账号恢复；按选定认证方式落实 |
| 展馆 | 创建、读取和修改馆资料 |
| 展品 | 创建、保存、读取和移除旧物 |
| 素材 | 图片音频上传、生成模型保存、校验及授权读取 |
| 三维生成任务 | 创建、查询执行状态、查询已有结果与显式重试；用户不能查询他人任务 |
| AI 整理 | 基于已保存的指定版本生成草稿 |
| 确认 | 明确确认当前版本 |
| 发布 | 检查全馆状态并生成快照 |
| 分享 | 登录后凭有效链接读取当前快照；停止分享、更换链接按个人归属授权 |
| 健康检查 | 返回应用和关键依赖是否可用 |

公共请求、响应与错误结构统一维护。身份与个人工作台已接入；生成任务和模型资产契约仍由 C 统筹。三维服务沿用[服务调研](13-D-三维生成服务调研.md)记录的演示 concept 反代与生产 Pro 云 API 两条路径；适配器已有假上游验证，应用侧任务编排、持久化与模型发布接口尚未接入。本表中的目标职责不表示对应路由均已存在。

公开展示与分享接口只返回公开展示数据，不包含原始讲述和 AI 内部草稿；受保护的工作台接口按权限返回编辑所需字段。所有接口均不得泄露存储路径或凭据。

素材接口使用第 9.7 节的限额，所有业务接口采用第 9.8 节的错误契约。成功响应统一为 `{ data: ... }`。

### 9.5 分享与素材

参观链接采用服务端生成的高熵随机 token，访问条件为“登录后持有效分享链接访问”。参观者不必是展馆所有者，登录不授予私有草稿或制作权限。

页面、数据和私有素材请求均在服务端检查有效会话、当前 token、分享状态和快照；素材还需属于当前发布快照，原始上传不进入公开静态目录。未登录或会话失效的数据和素材 API 返回 401 `UNAUTHORIZED`，不返回展馆内容。正式参观页面已接入服务端登录检查，未登录时跳转登录页并通过受限站内地址返回原链接；实际验收结果见验收清单，不能以 API 回归代替页面验收。

对外展示、缩略图和贴图使用正确处理方向、清除定位及设备敏感元数据的图片版本。若保留原始文件，只允许相应授权访问，分享接口不能绕过处理直接返回原图。

停止分享或更换链接后，旧 token 不能发起新的有效访问。私有及可撤销分享内容禁止存储缓存，需检查应用框架与代理配置；素材响应使用经过验证的 Content-Type 和 X-Content-Type-Options: nosniff。已经下载的副本不承诺撤回。

### 9.6 模型资产与空间约定

| 项目 | 固定约定 |
| --- | --- |
| 格式 | GLB，贴图内嵌 |
| 坐标与单位 | 右手坐标系，Y 向上，正面朝 +Z，长度单位为米 |
| 原点 | 交付模型的底部中心位于原点 |
| 入柜适配 | 使用包含节点变换的完整包围盒，按柜格宽、高、深计算最小等比缩放，三轴均预留 10% |
| 恢复目标 | 根据稳定柜格布局与模型初始变换计算，独立于动画中间状态 |
| 不合规资产 | 内置资产入清单前修正，生成资产入库前校验规范化；不在渲染代码中增加逐件临时补丁 |
| 资产引用 | 明确区分内置模型与生成模型；后者引用服务端资产 ID 和版本，不接受客户端指定任意 URL |
| 追溯字段 | 输入照片与来源版本、生成任务、模型资产版本、来源与许可、近似程度、缩略图；内部存储路径不公开 |

生成模型按不可信外部资产处理，完整解析后检查文件大小、几何体和纹理资源预算及外部引用；输出采用贴图内嵌 GLB，拒绝任意外部地址依赖。具体资源上限由 A、D 实测冻结后写入共享契约，由 C 在入库边界执行。模型通过校验后纳入私有存储和快照素材集合，读取与撤销沿用图片、音频规则，不能将供应商临时地址直接作为永久分享地址。

柜格尺寸指可用于摆放的内部宽、高、深。缩放系数为 `0.9 × min(格宽/模型宽, 格高/模型高, 格深/模型深)`，适配后各轴占用不超过该轴可用尺寸的 90%。

窗口尺寸或布局变化后，按新布局重新确定恢复目标，不从动画中间位置采样覆盖基准。

坐标和单位依据 [glTF 规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#coordinate-system-and-units)；原点、边距属于本项目约定。

### 9.7 上传格式与限额

| 项目 | 首版取值 |
| --- | --- |
| 图片格式 | 静态 JPEG、PNG、WebP |
| 图片文件上限 | 10 MiB，即 10,485,760 字节 |
| 图片尺寸 | 宽、高各不超过 8192 像素，且总像素不超过 32,000,000 |
| 音频格式 | MP3、M4A（AAC）、WAV（PCM） |
| 音频文件上限 | 20 MiB，即 20,971,520 字节 |
| 用户直接上传模型文件 | 不开放；用户上传照片生成模型 |
| 建模输入照片数量与拍摄要求 | 已实现单图与正背左右四视图的照片准备和保存，尚未提交生成任务；真实服务支持范围与拍摄要求由 D 实测、A 确定，生成前另校验服务要求及每次任务总量 |
| 生成模型输出 | 贴图内嵌的 GLB；字节数、面数、纹理及解析资源预算由 A、D 实测确定，C 在入库边界执行 |

字节与像素限额均检查原始输入，不能先完整解码超限图片再缩小。像素值作为首版资源预算，后续通过实际素材和部署环境验证；图片处理库支持设置输入像素限制，参考 [Sharp 文档](https://sharp.pixelplumbing.com/api-constructor/)。

允许格式、文件签名与实际解析结果需要一致，不能只凭扩展名或客户端 Content-Type 接受上传。音频还需在实际验收浏览器上验证播放。格式不在允许范围时返回 415；允许格式的文件损坏或图片尺寸超限时返回 400；文件字节数超限时返回 413，具体错误码见下一节。

### 9.8 错误契约

下表为现有错误码。生成任务的服务故障、处理失败和用量限制需在实现前由 C 与 D 补充稳定错误码、HTTP 映射及前端处理；文字 AI 的 30 秒超时和错误不能直接当作三维生成的完整契约。

失败响应的基础结构为 `{ error: { code, message, requestId } }`。message 提供可理解的操作提示，requestId 用于关联诊断；错误响应不泄露凭据、内部路径或私密内容。

`NOT_CONFIRMED` 返回 HTTP 409，并必须包含 `error.details.unconfirmedExhibitIds`。其余错误维持基础结构。示例：

```json
{
  "error": {
    "code": "NOT_CONFIRMED",
    "message": "请先确认列出的展品后再发布。",
    "requestId": "request-example",
    "details": {
      "unconfirmedExhibitIds": ["exhibit-example"]
    }
  }
}
```

`unconfirmedExhibitIds` 是非空、无重复的展品 ID 数组，只列出当前已授权展馆中未删除且当前版本尚未确认的展品。前端通过该字段定位需要处理的展品，不从 message 解析清单；身份、归属和版本校验仍按既有规则执行。

| HTTP | 错误码 | 含义 |
| --- | --- | --- |
| 400 | VALIDATION_ERROR | 字段、尺寸或文件内容校验失败 |
| 401 | UNAUTHORIZED | 未登录、会话失效、认证失败或登录/注册尝试受限 |
| 403 | FORBIDDEN | 已识别身份不允许执行该操作 |
| 404 | NOT_FOUND | 受保护资源不存在或对当前身份不可见 |
| 404 | SHARE_NOT_FOUND | 分享不可用，或素材不属于当前分享快照 |
| 409 | VERSION_CONFLICT | 预期版本与当前版本不符 |
| 409 | MUSEUM_EXISTS | 当前账号已有有效展馆，应继续编辑原展馆 |
| 409 | NOT_CONFIRMED | 发布内容尚未完成当前版本确认 |
| 413 | PAYLOAD_TOO_LARGE | 上传文件或 JSON 请求体字节数超限 |
| 415 | UNSUPPORTED_MEDIA_TYPE | 文件格式或编码不在允许范围 |
| 502 | AI_UNAVAILABLE | 模型服务失败或输出不可用 |
| 504 | AI_TIMEOUT | 模型调用超时 |
| 500 | INTERNAL_ERROR | 未预期的服务端错误 |

需要隐藏资源存在性的受保护入口使用 NOT_FOUND；FORBIDDEN 不用于暴露当前身份不可见的私有资源。分享入口不区分 token 失效、素材不存在与素材无权访问，统一返回 404、SHARE_NOT_FOUND 和相同的对外提示。

版本冲突返回 409、VERSION_CONFLICT，前端保留未保存输入，提示刷新或核对差异，不自动覆盖或盲目重试。

## 10. 怎样判断完成

### 10.1 验证触发与范围

| 触发条件 | 执行范围 |
| --- | --- |
| 修改局部逻辑、页面或样式 | 验证受影响的不变量与关联流程，选择相关场景和设备 |
| 工程初始化 | 建立类型检查、lint、业务测试和生产构建的实际入口，并落实相应 CI 检查 |
| 首次完整上线或影响多个核心流程的变更 | 执行适用制作模式下的完整核心流程验收，覆盖第 10.2 节全部适用场景及桌面、手机操作 |
| 实际部署 | 核对生产构建、静态模型、原生依赖，并验证重启后数据和素材仍可读取 |

## 12. 后续功能想法

记录日期：2026年10月23日。来源为本次提供的功能讨论截图，状态为已收录、待范围取舍与排期。本节补充后续方向。个人账号和自助工作台已于 2026年10月24日进入第 4 节的方案 B 目标；公开发现、社交、会员、自传及共同创作仍待取舍，不因制作模式变更自动纳入本轮验收。

### 12.1 公开展示平台与私密定制交付

建设一个公开可见的网站，展示愿意公开自己纪念物和生平事迹的人的展馆。路人可以参观展品、阅读不同人的经历；网站同时作为作品展示平台和吸引定制客户的主要入口。

- 首页开局可以展示一个固定展馆，也可以每日随机展示一个展馆；两种方式作为候选，后续择定。被展示的作品必须已获准公开。
- 希望私密定制的客户，制作完成后可以在网站内的个人私人展馆查看，也可以选择只包含自己展品的独立网站。
- 公开展馆可以进入发现、搜索、地图和排行榜；私人展馆不进入这些公开入口。
- 私人展馆及独立网站的访问方式需另行确定，例如持链接访问或指定账号访问。独立网站只是交付形态，本身不代表私密；现有分享链接准确描述为“登录后持有效分享链接访问”。

用户身份、个人工作台和现有资源的个人归属隔离已接入。公开平台、额外访问方式和独立网站托管维护另行取舍，不能将自助账号视为已实现上述全部能力。

### 12.2 “世界”入口、好友互动与展馆发现

在主界面左上角设置“世界”入口，打开后按“附近的人 → 好友 → 排行榜”的顺序组织发现入口，并提供搜索。用户可以进入他人的公开个人博物馆，在留言区留言或收藏（star）。

进一步提供全球视角：用户选择想看的地域，参观当地个人或多人共同展馆。好友关系的建立方式、“附近”的地域范围、搜索字段及留言管理方式仍需确定。

地图与榜单的设想：

| 能力 | 想法 |
| --- | --- |
| 全球地图 | 按地域发现展馆；时间不足时可先覆盖中国 |
| 热门展馆亮点 | 个人或共同展馆超过 1 万人浏览后，在地图对应地区点亮；亮度随浏览量档位变化 |
| 总浏览量榜 | 按展馆累计浏览量排行 |
| 收藏榜 | 按展馆收藏（star）数量排行 |
| 近期浏览量榜 | 提供年、月、日的浏览量排行 |
| 国家维度榜单 | 按国家筛选展馆的浏览量榜和收藏榜；首期也可只做中国范围 |

“超过 1 万人浏览”作为当前讨论中的亮点门槛记录，浏览人数与浏览次数需区分。亮度分档、有效浏览与访客的去重口径、年/月/日采用自然周期还是滚动窗口，以及国家维度是否还需要国家间汇总排名，均待确定。

平台可发现的“公开”需要明确授权，不能将已有参观链接自动收录进首页、搜索、地图或榜单。附近和地图位置采用用户同意展示的地域信息，不默认展示精确住址或实时位置。作品退出公开展示后，应退出相应发现入口。

### 12.3 AI 访谈与个人自传

在未来的个人工作台中增加“个人自传编写”选项。用户进入后与 AI 对话，AI 通过逐步提问帮助回顾经历，再把用户提供的内容整理成自传草稿。

- 可调研并引入 GitHub 上的自传编写 skill，借鉴其访谈与整理流程；具体仓库尚未提供，采用前核对内容、许可及适配方式，不直接执行未经检查的外部脚本。
- 用户可以补充、修订并确认自传，AI 保留记不清或不确定的内容，不补造人生经历。
- 确认后的自传以书籍形式放在博物馆中央，封面显示用户名，参观者可打开阅读获准展示的内容。
- 对话记录、自传草稿和确认后的展示版本分别保存；自传公开范围由用户决定，不随展馆公开而自动公开全部访谈内容。

这项能力依赖个人工作台、长篇内容保存与书籍阅读交互，需另行明确篇幅、章节形式和确认方式，不直接套用首版短展签的字数限制。

### 12.4 邀请共同作者

制作展品或故事作品时，可以邀请相关作者，用于呈现两人或多人之间的关系和回忆。被邀请人可以接受或拒绝；接受后才作为共同作者展示，待回应或已拒绝不能被当作共同署名已获同意。

共同作者可以是共同经历的讲述者或内容贡献者。共同署名、编辑权限和发布确认是不同的事项：是否允许共同编辑、哪些修改需要谁确认，以及退出合作后的署名和内容如何处理，均在实现前明确，不能由邀请接受操作自动推定。

### 12.5 不依附实物的故事展品

展品不必局限于具体旧物，也可以是一段经历、一段人与人之间的故事，或一个时代的记忆。没有对应实物也能作为独立内容被收藏和参观，不要求用户为了建展品而虚构物品或提供无关照片。

可探索以故事卡、信件或书页作为柜内入口，选中后展示文字、照片与原声；这些是呈现候选，尚未确定最终形式。时代背景与个人回忆需要区分来源，AI 仍只整理有依据的内容。

采用该方向时需调整当前以旧物名称、实拍和模型为中心的收录与展示契约，明确故事类展品的必填内容及无实物时的参观方式。

### 12.6 多人共同记忆

展馆和展品可以承载多人的共同记忆，既可以围绕共同纪念物，也可以围绕一段共同经历：

- 情侣或夫妻的爱情故事与纪念物。
- 创业团队的共同经历与阶段纪念。
- 社区、社会组织等群体的共同记忆与纪念物。

同一作品可以保留不同参与者的讲述，并标明各自来源；记忆不一致时不由 AI 合并成一个确定事实。涉及共同署名时衔接第 12.4 节的邀请机制，公开内容及人物信息按相应授权范围展示。

共同记忆是内容方向，不等于必须先建设实时协作或多级组织权限。关系展示、多人确认和后续维护由谁负责，需要在该功能进入实施范围时确定。
