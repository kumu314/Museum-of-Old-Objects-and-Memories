# B 工作台界面与交互方案

记录日期：2026-10-24。本文记录本次界面讨论的已确认选择、实施建议与待确认细节，不代表页面或功能已经实现。

产品范围、数据与发布规则沿用 [开发书](PROJECT_PLAN.md)，模块职责沿用 [团队执行方案](TEAM_EXECUTION_PLAN.md#32-b用户自助制作与参观界面)。实际进度和验收结果分别见 [实施状态](IMPLEMENTATION_STATUS.md) 与 [验收清单](11-验收清单.md)，本文不另维护功能完成状态。

## 1. 已确认的产品与交互选择

| 项目 | 本次确认结果 |
| --- | --- |
| 整体基准 | 用户提供的深色、暖金、木质六格展柜、三栏单页工作台截图，同时作为布局与视觉参考 |
| 视觉要求 | 减少模板化装饰和“AI 味”，突出真实旧物、照片与回忆 |
| 保存方式 | 手动保存草稿；保存、确认当前版本和发布分享是独立操作 |
| 展柜 | 左栏接入 A 的实时 3D 展柜，每页六格，柜外翻页，全馆不限于六件 |
| 展品选择 | 单击柜内展品只切换编辑对象；另设“检视模型”入口进行旋转和缩放 |
| 检视位置 | 在当前页面内放大查看，返回后保留原有输入和选中展品 |
| 手机布局 | 使用“素材 / 故事 / 确认”三个页签，切换保留输入，顶部持续显示当前展品与保存状态 |
| 新建顺序 | 填写名称与共同回忆，再上传照片，生成并预览模型 |
| 内容范围 | 每件展品对应实物，重点记录它承载的共同回忆；独立的无实物回忆不进入本次界面范围 |
| 回忆输入 | 一个自由讲述文本框，配可选提示，不强制拆成人物、时间和事件等必填项 |
| 生成操作 | “生成 3D 模型”与“整理故事”分别触发、分别显示状态和结果 |

共同回忆按当前用户提供的讲述保存；内容涉及多人不自动引入邀请、共同编辑或多人确认功能。

## 2. 三栏内容安排

以下为依据已确认选择整理的界面安排建议，具体尺寸与材质效果通过实际页面预览核对。

| 区域 | 内容与职责 |
| --- | --- |
| 顶部 | 返回展馆、当前展品名称、明确的草稿保存状态与保存入口 |
| 左栏 | 实时 3D 六格展柜、名称与约略年代、照片和可选原声、模型生成与候选结果入口 |
| 中栏 | 自由讲述、单独保存的录音整理文本、可选回忆提示、故事整理操作、AI 草稿及来源对照 |
| 右栏 | 人工编辑的展签、当前版本与确认状态、确认记录、发布及分享操作 |

可选回忆提示建议为：“它与你和谁有关？”“你们一起经历过什么？”“为什么想把它留下来？”允许略过，保留用户自己的叙述顺序及不确定表达。

原始讲述、录音整理文本、AI 草稿和最终展签保持各自身份。AI 草稿须经审阅与明确采纳；整理失败时仍可人工编辑。

手机端将左栏、中栏、右栏分别收纳到“素材 / 故事 / 确认”页签。三个页签共用当前编辑对象与草稿，切换不清空输入、不自动保存，也不重新提交生成任务；顶部持续显示当前展品与保存状态。宽屏三栏与手机页签使用同一套编辑数据。

## 3. 视觉执行建议

- 保留三栏骨架，用留白、对齐和细分隔线组织层级，减少层层套卡片。
- 木柜承担主要材质表现，编辑区采用平实的深色背景。
- 暖金集中用于选中格位与关键操作，正文、边框和次要按钮保持克制。
- 标题少量使用宋体风格，正文与操作使用清晰的系统字体，保证中文行距和可读性。
- 照片、音频信息、任务状态与来源标签使用实际数据；没有对应数据时显示空态或明确的不可用状态。
- 展签字数沿用公共契约的 120 字上限；当前先沿用纯文本编辑，不照搬截图中的 500 字计数和富文本工具栏。
- 故事 AI 的来源标识继续清楚展示。当前契约提供草稿级来源片段集合，界面不得据此虚构逐句对应关系。

## 4. 关键操作规则

### 4.1 新建与保存

1. 用户选择空格后开始收录实物，先填写名称与共同回忆，再补充照片及展示信息。
2. 新建空态明确下一步操作；尚无模型时保留照片与文字入口，不放入假生成结果。
3. 编辑后显示“有未保存修改”，发起保存时显示“正在保存”，仅在保存成功后显示“已保存”。
4. 保存失败保留输入并说明下一步；版本冲突保留本地输入供核对，不自动覆盖。
5. 切换格位、返回和重新读取时处理未保存输入。确认和发布以已保存的当前版本为准。

现有保存接口还要求完整的展示说明等字段。名称和回忆优先的界面顺序不代表已经支持只含这两个字段的提前持久保存；落地时需明确其余字段的收录位置，若要提前保存不完整草稿，由 C 协调契约后再实现。

### 4.2 展柜与检视

- 单击展品同步当前编辑对象、素材、讲述和展签，选中格位清晰可见。
- “检视模型”在当前页面内放大查看，单独触发取出与旋转缩放，提供返回按钮与 Esc 返回。
- 放大和返回复用同一个场景实例，保留选中展品、已保存版本及未保存输入；布局变化不重置编辑表单。关闭检视后将键盘焦点交还检视入口。
- 切换展品停止旧音频，音频由用户主动播放。
- 展柜复用 A 的场景和控制器，选择状态保持唯一来源；“选择编辑”与“取出检视”的区分需与 A 对齐，不在 B 内复制另一套三维状态。
- 模型或 WebGL 故障时显示明确反馈，照片和故事仍可访问。实时展柜使用一个 Canvas。

### 4.3 两类生成与确认

- 模型生成与故事整理各自读取已保存的有效输入，分别显示状态，不由一次失败触发另一操作的重复提交。
- 生成模型先成为候选结果，由用户预览并明确采纳；故事草稿经来源核对、修订及采纳后成为展签内容。
- 生成和采纳不自动完成确认或发布。确认范围覆盖当前版本的模型、展签及展示素材。
- 采纳新模型或修改公开内容后，按服务端结果呈现旧确认失效及需要重新确认的状态。
- 发布前显示需要处理的展品；照片平面展示缺图时，允许保存草稿，但须补图并保存后才能确认和发布。草稿修改不直接改变已发布快照。
- 参观页、快照数据和素材均要求有效登录会话及当前分享链接；登录或注册后按自己的展品分流，继续参观他人时再次打开原链接，不赋予访客私有草稿权限。

## 5. 实施顺序与交接

| 顺序 | 交付内容 | 检查重点 |
| --- | --- | --- |
| 1 | 工作台三栏结构、手机页签、新建空态、名称与回忆输入、保存反馈位置 | 视觉对照参考图，真实中文输入，页签切换保留输入，空数据与长文本布局 |
| 2 | 接回现有编辑、保存、照片/音频上传、故事整理与人工确认 | 保存恢复、输入保留、来源对照、过期草稿、版本冲突；失败状态可操作 |
| 3 | 与 A 接入实时展柜，完成选择编辑与同页放大检视 | 唯一选择状态、快速切换、返回后保留输入、音频停止、键盘焦点、模型与 WebGL 故障入口 |
| 4 | 接入 C、D 交付的真实模型任务与候选采纳 | 真实状态、刷新恢复、来源过期、提交结果不明与用量限制反馈 |
| 5 | 与正式参观页贯通发布及分享操作 | 当前版本确认、快照展示、链接交付、换链与停止分享 |

步骤 2 与步骤 3 可按接口交接情况安排；模型任务尚未可用时，已授权且不依赖它的界面工作继续推进。每一步检查桌面、窄屏、键盘和中文输入，最终由 E 组织真实手机与普通用户全流程试用，结果登记到既有验收清单。

已有入口集中在 `src/features/studio/`；展柜和检视复用 A 的实现。首页与注册/登录页已由另一个 agent 完成，本轮沿用视觉；按新决策修改登录分流，首页收藏按钮统一进入 `/studio`（未登录再到登录页），全局样式不变。新增完整流程与接口准备见 [个人展馆流程](PERSONAL_MUSEUM_FLOW.md)。

## 6. 第一阶段实施范围

第一阶段先完成工作台结构与收录表单的调整，以现有 `src/features/studio/museum-workbench.tsx` 和 `src/features/studio/exhibit-editor.tsx` 为主要入口。工作台专用样式限制在所属页面或组件；涉及首页、登录页及全局样式的共享修改先核对另一位作者的范围。

- 桌面提供参考图的三栏结构，安排好展柜容器、素材、讲述、草稿和确认区；三维接入仍按第 5 节与 A 交接。
- 手机使用已确认的三个页签，顶部持续保留当前展品及保存状态。
- 新建先突出名称与自由讲述，提供可选回忆提示；尚无素材、草稿和模型时显示真实空态。
- 调整表单布局时保留现有编辑与保存行为；保存反馈取自实际操作结果，未接入的能力明确显示不可用。
- 检查输入不丢焦点、不打断中文组合输入，切换页签与改变窗口宽度不丢失草稿。

这一阶段交付可实际操作的布局与表单供视觉核对；不将其记作真实建模、完整三维联动或发布参观已验收。
