记录日期：2026-10-24。依据开发书 §9.6 与当前展柜实现。本文件说明 D 的资产交付责任，不修改共享契约，也不表示三维生成链路已实现或验收。

## 给 A 的三个明确答复

| 问题 | 本轮决定 | 执行责任 |
| --- | --- | --- |
| 模型正面 +Z 还是 −Z | **沿用 +Z**，右手坐标系，Y 向上。相机观察方向与模型正面是不同概念，不因此在渲染端统一补转 180°。 | D 在资产入库前校正；A/E 对照参考照片确认语义正面。 |

| 尺寸归一化归谁 | **D 负责资产尺度与依据，A 负责陈列 scale。** 交付米制模型，底部中心为原点；不悄悄把最长边统一到 1 米。 | D 使用可靠实测尺寸完成标定；A 沿用完整节点包围盒与陈列比例适配。 |

## 尺度必须有依据

普通照片没有已知尺寸参照时，无法确定唯一的真实物理尺寸。“单位写成米”、外观看似合理或供应商返回单位长度，都不是实测证据。

- 已有用户测量、带尺度参照的输入或其他可靠尺寸：记录来源、测量轴向与数值，将资产标定到米。
- 供应商输出最长边为 1 或其他任意尺度：视为未标定结果，不能直接当作真实米制尺寸；先依据可靠尺寸恢复尺度。
- 尺度未知：优先请用户补充至少一个可对应模型轴向的物理尺寸。是否允许估算预览由 A 决定；允许时明确标为估算/未知，不能据此宣称真实相对大小已验收。
- 尺度来源、标定状态和显示说明由 C 维护一份权威 schema、B 呈现；本文件中的说明不作为已经存在的接口字段。

## 陈列适配不等于资产归一化

当前 `src/features/cabinet/model-fit.ts` 使用完整模型包围盒，对柜格宽、高、深取最小等比缩放，并保留三轴至少 10% 空间；当前原型还通过 `maximumScale` 保留样例的统一米制陈列比例。对应调用在 `cabinet-stage.ts`，共同比例在 `cabinet-layout.ts`。

D 不把该陈列倍率烘焙进交付资产，不从动画中间变换推导原点或尺寸。A 不为每件生成物添加不同的方向/单位补丁。对异常包围盒、非有限数值、零尺寸或无法确定正确变换的结果，先报告处理失败。

现有样例的毫米参数是演示建模约定，不是用户藏品实测尺寸。当前渲染器的居中/落底处理也不能代替生成资产入库前规范化。

## 供应商结果的验收清单

服务已选定腾讯混元 3D：演示路径采用本机网页反代的 concept 通道，生产路径保留专业版官方云 API。两种适配器均尚未接入应用的持久化任务与发布链路；以下处理由 D 实现并验证，目前均不得仅凭供应商宣传标为完成：

1. 完整下载、限制文件与解析资源，检查 GLB 容器及实际场景。
2. 拒绝不支持的必需扩展、任意外部网络资源引用和损坏的图片/几何体数据；供应商临时 URL 不作为永久分享地址。
3. 输出贴图内嵌、当前加载链可直接解析的 GLB，遵守 +Z/Y-up/底部中心。
4. 完整计算包含节点变换的包围盒，记录米制尺寸及标定依据。包围盒本身不能证明语义正面或真实尺寸。
5. 与 A 在目标电脑和实际手机上实测后，冻结文件大小、几何体、纹理及解析预算；未冻结前不填写无依据的通过阈值。
6. 给 C 返回可保存的完整结果、预览、来源、近似程度和失败原因；C 负责身份归属、任务、版本、私有保存、快照与撤销。
7. 用新的获准照片得到真实结果，由 A/E 验证入柜、选择、检视、返回和失败时故事入口；内置模型和照片薄片不冒充生成结果。

## 当前边界

主线已具备内置与动态模型展示，以及混元 3D Pro 官方云 API 和 concept 网页反代两个服务端适配器（本地假上游验证）。生成模型的个人归属、任务编排、入库及发布契约、尺度状态字段和资源预算仍待接入或冻结。展示端的动态 GLB 加载与预览能力不能代替这些服务端边界及方案 B 完整验收。

2026-10-24 已记录 concept 通道独立生成的文生几何白模样本及本地解析验证；它没有材质或贴图，不是图片生成与纹理阶段的完整成品，也不证明应用生成链路已接通。官方云 API 尚无真实调用验收记录。本文件不授权新增素材外传或付费任务。

选定服务的官方资料与演示白模历史见 [D：照片生成 3D 服务调研](../../../docs/13-D-三维生成服务调研.md)。官方资料、独立样本、适配器测试和应用完整流程的证据须分别判断。
