# A：展柜与检视原型

更新于 2026-10-24。本目录与 `../viewer/` 为 A 的独立实现，基线 `b93cc46`。这是可操作的三维原型，尚未接入 C 的公共展示 schema、发布快照或 B 的正式故事与音频面板，不能视为完整产品或 G4 已完成。

## 入口与边界

- `cabinet-stage.ts`：`mountCabinetStage(canvas, items, controller, options)`，一个 Canvas，消费展品 ID、格位和受信任模型键。返回 `retry()`、`retryModel(id)`、`resetView()`、`setEditing(enabled)`、`setArrangement(arrangement)`、`destroy()`；`onSlotDrop(id, targetSlot)` 只上报换位意图，由调用方更新权威陈列数据。
- `../viewer/inspection-controller.ts`：`createInspectionController(ids)`，提供选择、返回、订阅和带 transitionId 的完成通知；旧回调无法完成新动画。
- `model-fit.ts`：完整节点包围盒的最小等比适配与底部中心落点，三轴均保留至少 10%；当前三件米制 GLB 共用 `cabinet-layout.ts` 中的 `MODEL_UNITS_PER_METRE=14.18`，不再逐件按柜格宽度放大。
- `cabinet-arrangement.ts`：演示陈列条目的校验、六格移动/互换和铭牌文字修改；每件展品恰好出现一次，格位为互不重复的整数 0–5。
- `model-manifest.ts`：固定模型键及来源、版本、许可和近似程度；不接受用户输入的模型 URL。
- `demo/index.html`、`demo/main.ts`、`demo/style.css`：可移植的演示页面源文件。没有另建业务契约，也没有修改项目根配置或依赖锁文件。
- `demo/qa.html`、`demo/qa.ts`：单独检查台，支持视口、WebGL 中断、减少动态 fixture、合成悬停和静止一秒 RAF 计数；不是参观页面的操作入口。

接入时在客户端挂载场景，并在对应生命周期调用 `destroy()`。调用方必须先按公共契约校验数据。`inspectionInset()` 返回覆盖画布的右侧面板宽度（像素）；窄屏面板在画布下方时返回 0。`onSurfaceStatus` 应显示故障说明、隐藏失效画布并保留图文入口；`onAssetStatus` 提供加载和失败状态。B 从同一个 controller 订阅当前选择，并在切换时停止旧音频，默认不自动播放。

### 编辑操作与保存边界

1. 点击右上角“编辑陈列”。若正在检视，先沿原四态流程放回，回到 `overview` 后才进入独立编辑模式；完成编辑仍留在总览。
2. 将展品拖到六格中的空格会移动，拖到有展品的格位会交换。格位按上排左至右 1–3、下排左至右 4–6 编号；不支持格内任意坐标摆放。拖出有效格位或按 Esc 取消本次拖动。
3. 展开底部“修改铭牌 / 选择格位”，可用带标签的展品与格位下拉框及“移动 / 交换”按钮完成同样操作，支持键盘；工具面板可以收起，避免遮挡拖动区域。
4. 铭牌在显式点击“保存铭牌”后才应用，去除首尾空白，内容不能为空，最多 24 个 Unicode 码点。不会随逐字输入重建场景，也不会修改展品固定名称、样例说明或模型来源。铭牌随展品换位。
5. 点击“完成编辑”退出。普通参观仍采用 `overview → focusing → inspecting → returning`，点击展品取出、旋转缩放、返回和 Esc 的检视语义保留。

`demo/main.ts` 拥有陈列的权威状态，保存到同源浏览器的 `localStorage` 键 `shiwuguan.demo.arrangement.v1`，记录结构为 `{ version: 1, arrangement: [{ id, slot, plaqueText }] }`。初次无记录时使用清单中的展品名称与“年代待考”。读取时校验版本、完整 ID 集合、唯一格位及铭牌；无效记录会明确提示并使用初始陈列，在用户实际修改并保存前不覆盖旧记录。存储失败会提示当前画面已更新但刷新可能丢失。清除站点数据、换浏览器或换源不会共享这些修改。

这只是本地演示编辑：没有服务器保存、团队身份、物主确认、发布快照或多人同步；“分享参观”和“音画设置”继续保持未接入状态。编辑文本按文本绘制，不解释 HTML。

## 历史精修（2026-10-23 清晰度与暖金调色）

以下保留当时的实现及验证证据。磁带/车票的照片薄片、独立陈列宽度和旧资源数量已被上方当前实现取代，其余照明与柜体视觉仍按实际源码为准。

继续沿用 `feat/cabinet-inspection` 中的原型和既有 17681 预览。本轮没有改六格落点、镜头构图公式、检视控制器或页面业务脚本；只按请求简化外框、灯口并调整材质、照明与导航样式。没有提交或推送。

- 本项目是原生 Three.js，使用 `setPixelRatio(Math.min(2, Math.max(1, devicePixelRatio)))` 实现 DPR 1–2。原有 sRGB 设置保留；磁带/车票和木纹贴图使用渲染器支持的最大 anisotropy。
- 正面原图裁片仅为磁带 240×146、车票 272×146。现在绘制到宽 2048 的 CanvasTexture（同比例高度），作轻量对比度调整和局部 unsharp mask；保持原有 UV、文字和轮廓。工作画布放大不代表补出了原图缺失信息。
- 照片已含光照，因此磁带/车票正面改为 `MeshBasicMaterial`，关闭该正面的 tone mapping，避免再次照亮而洗淡墨迹；侧面和背面仍用原物理材质。移除磁带的雾化盖层，正面/卷轴浅浮层共用一个材质。
- 真正影响 overview 清晰度的另一处是前玻璃的二次透射采样：玻璃粗糙度改为 0，`transmissionResolutionScale=2/pixelRatio`，将透射缓冲保持在每 CSS 像素约两份采样。它增加透射缓冲的显存与像素处理成本；没有新增持续 RAF。
- 竖向玻璃反光与玻璃环境统一为香槟金（#ffd699 / #c88a4b），内口四边增加 0.009 宽深铜高光线，底板增加随现有坡度贴合的暖琥珀光斑。
- 顶灯改成顶板前口的零厚度椭圆亮片，没有圆柱边缘或深色灯壳；#fff6e0 暖白中心配 #f09c36 辉光。外框改为同宽 0.23 的四条实木板，真实轮廓形成 45° 斜接，保留背后的承重箱体。

## 历史视觉与资产（2026-10-23 A/B/C 记录）

保留原相机、磁带、车票模型、六格位置、检视四态和页面操作。镜头使用 26° 透视视角、按宽高约束拉远；overview 的观察点为 y=-0.215，镜头 y=0.5。1600×900 内容视口下，柜体约占宽 81%、高 77%，上下宽度差约 2%；原柜体高宽比和现有导航/页脚边界限制了同时满足参考 92%/80% 的构图，不拉伸 Canvas 或展柜来凑比例。

- `cabinet-body.ts`：板材微倒角、分板方向与 UV 偏移、格内压条、每格 0.32 高的正面横框、连续落地底座。展示底板和展品的恢复位置不变。
- `brass-plaque.ts`：宽 1.96、高 0.235、厚 0.043 的倒角黄铜牌，约为格宽 58.5%；旧黄铜渐变、横向拉丝粗糙度及微弱 bump、两颗带凹槽圆头螺钉。文字纹理 1600×192，牌面同比例、400 字重，无 fillText 横向压缩。铭牌内容取 model-manifest 的 displayName / eraLabel；当前三件均缺少经核实年代，显示“年代待考”，详情原有来源说明保留。
- 胡桃木使用原有 Poly Haven diffuse / roughness / OpenGL normal，normalScale=0.22，metalness=0；源纹理宽 1.8 m 对应约 6 场景单位，横框/竖框分方向。ACES 曝光 1.0、sRGB 输出。移除原背板的橙色发光覆盖与光雾。
- 六格各有一个内嵌玻璃实体：厚 0.014（按比例约 4.2 mm）、IOR=1.5、transmission=1、opacity=1、roughness=0.008。不是降低透明度的白色遮罩。玻璃不在展品拾取集合中。
- `warm-environment.ts`：原 RoomEnvironment 保留用于物体和木材；玻璃使用独立 PMREM，三张不同宽高、位置和强度的柔光卡真正进入烘焙环境。开/关玻璃环境反射的同镜头实拍对照已保存。地面 Reflector 的嵌套渲染排除玻璃，避免覆盖主镜头透射缓冲；恢复 WebGL 时重新建立两个环境。
- 六盏暖色 SpotLight，格内上亮下暗；环境补光保持较弱。方向补光不投硬边阴影，格内接缝和展品底部沿用显式接触遮蔽，尚非路径追踪的物理软阴影。
- `gallery-surroundings.ts`：连续深色地面、低强度 25 点模糊倒影、底部接触影。地面和反射在远处及屏幕下缘渐隐。背景使用跨整页的低对比暖色模糊轮廓，不使用目标图作场景背景。

总览鼠标视差、格位悬停反馈、返回及模型恢复逻辑保持原样。静止后停止请求渲染帧。指标仅在 demo URL 带 `?metrics=1` 时采集到 Canvas 的 data-render-stats；CPU render 耗时不等于 GPU 耗时或真实显示帧率。
