# SQL 迁移

执行 `pnpm db:migrate`，配置从进程环境及 `.env.local` 读取。连接目标是 `DATABASE_URL`，不是测试库。

业务迁移由 C 按数据契约新增，文件命名为 `0001_description.sql`、`0002_description.sql`，从 0001 连续编号。已应用的 SQL 不再修改或删除；追加新迁移修正。文件只能包含事务内可执行的 SQL，不自行写 `BEGIN` / `COMMIT` / `ROLLBACK`，不使用 `CREATE INDEX CONCURRENTLY` 等事务外操作。

执行器使用 PostgreSQL 事务、事务级互斥锁与 `schema_migrations` 校验和账本；重复运行不重复应用，历史被修改时失败。所有待应用迁移及账本一起提交，失败一起回滚。不要手工修改账本或通过清库解决迁移冲突。

截至 2026-10-29，迁移连续至 `0023`。前五项为初始模型与会话、用户归属、登录/注册节流分区，以及个人唯一展馆、跨页格位和建模照片准备；`0006`、`0007` 为建模任务、私有模型资产和提交安全；`0008`—`0010` 为累计浏览、共同作者讲述及署名长度；`0011` 为生成模型入柜，`0012` 为发现收录授权；`0013`—`0015` 为三态访问、发现目录/关系与留言；`0016` 为自传记录。`0017` 冻结快照模型成员，`0018`、`0019` 为自传 AI 操作及用量，`0020` 为不随删书重置的账号日调用计数；`0021` 为单图生成账号日额度，`0022` 为停止已接受的共写，`0023` 为非自传文本 AI 展签整理的账号日额度。保留原型已应用的旧迁移，不重写内容和校验和。开发库使用 `pnpm db:migrate`，测试库使用 `pnpm db:migrate:test`，统一要求 PostgreSQL 18。

方向一新增迁移、发布与开链行为、空演示名单及尚未完成的业务见[方向一 API 与迁移](../docs/DIRECTION_1_API.md)。`0013` 保留旧有效链接为 link_only，不自动公开；`share_enabled` 只作为兼容投影，旧代码直接修改它会失败。发布现在只生成快照，开链另行明确操作。执行迁移前准备配套备份和恢复验证，并安排应用切换，不能让旧写入器与新代码混跑。各环境应用情况见实施状态；迁移文件存在不代表部署完成。

`0005_personal_museum_pages.sql` 遇到同一账号已有多座有效展馆时明确失败，整批待应用迁移一起回滚；须先备份并由馆主决定内容处理，不能自动删馆、清库或修改账本。旧分支的分叉迁移历史另按 [迁移兼容说明](../docs/PERSONAL_MUSEUM_FLOW.md#迁移与兼容) 协调。
